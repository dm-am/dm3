# Политика имен пользователей (Login)

## Правила валидации

### Модель: запрещающий список

Username может содержать **любые символы, кроме запрещенных** (deny-list, не allow-list).
Разрешенное не перечисляется: латиница, кириллица и другие алфавиты, цифры, `_`, `-`, `.`,
пробел (с ограничениями) — все проходит, если символ не входит в список ниже.

### Запрещенные символы

| Символ | Причина |
|--------|---------|
| `<` `>` | из них состоит разметка страницы: имя с ними может подсунуть читателю чужой скрипт |
| `"` | HTML-атрибуты, SQL |
| `'` | SQL, JS-инъекция |
| `` ` `` | JS template literals |
| `\` | Escape-последовательности |
| `/` | URL path separator |
| `?` | URL query string |
| `#` | URL fragment |
| `%` | URL encoding |
| `&` | URL parameters, HTML entities |
| `@` | Email confusion, mentions |
| `[` `]` | Markdown, JSON |
| `(` `)` | Markdown links |
| `{` `}` | Template syntax |
| `=` | URL parameters |
| `~` | Home directory, regex |
| `!` `$` `^` `*` `+` `|` `;` `:` | Shell/regex special chars |
| Control chars | Невидимые символы |
| Zero-width | Спуфинг имен |

### Правила пробелов

- Не в начале
- Не в конце
- Не подряд

### Правило содержания

- Хотя бы одна буква или цифра

Имя целиком из пунктуации адреса не имеет: имя пользователя это сегмент пути, а
точечные сегменты и браузер, и HTTP-клиент сворачивают до отправки запроса, так что
`/users/..` уходит на сервер как `/users/`.

### Правила длины

- Минимум: 2 символа
- Максимум: 20 символов

### Регистр (Case Sensitivity)

**Case-preserving, case-insensitive** — индустриальный стандарт (GitHub, Discord, Twitter):

| Аспект | Поведение |
|--------|-----------|
| Хранение | Сохраняет оригинальный регистр ("Adam Advena") |
| Отображение | Всегда оригинальный регистр |
| Все сравнения | **Case-insensitive** |

**Примеры:**
- Регистрация "Adam" → "adam" недоступен
- Логин: "adam" + пароль → войдет как "Adam"
- URL: `/users/adam` → профиль "Adam"
- API: фильтр по имени пользователя принимает "adam" → найдет игры мастера "Adam"

### Зарезервированные имена

"Аккаунт удален" не принадлежит никакой строке `Users`: этим именем подписано все,
что написали удаленные аккаунты, и по нему открывается профиль `/users/Аккаунт удален`,
который это собирает. Живой аккаунт под таким именем подписывал бы свои посты так же,
и читатель их не отличил бы, поэтому имя занято навсегда вместе со всеми написаниями,
которые читатель примет за него:

- другой регистр и "е" с точками вместо "е";
- латинские буквы вместо похожих кириллических (`a`, `e`, `o`, `p`, `c`, `x`, `y`, `k`,
  `m`, `t`, `h`, `b` и их заглавные);
- пробелы, `_`, `-` и `.`, добавленные, убранные или переставленные.

Регистрация, проверка имени и смена имени отвечают на такое имя тем же "занято", что и
на имя живого аккаунта, и больше ничего не сообщают. Удаленную строку с таким именем
(перенесенный общий аккаунт DM2) модерация не восстанавливает. Профиль по адресу
открывается только самим именем (регистр, пробелы по краям и "е" с точками не
важны), а не похожим написанием: похожее написание никому не принадлежит и отвечает
404, как любое неизвестное имя. Правило и его проверка записаны в
`src/DM.Domain.Core/Users/RemovedAccount.cs`.

## URL-стратегия

Используется URL-кодирование:

```
Имя:  "Adam Advena"
URL:  /users/Adam%20Advena
```
