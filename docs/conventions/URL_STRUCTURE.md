# Конвенции URL

Правила адресов страниц клиента. Не проверяется: маршруты живут в [router.ts](../../src/DM.Web.Client/src/app/providers/router.ts), сверка с ним ручная.

Здесь адреса страниц. Адреса API и их query-параметры описаны в [API_DESIGN.md](API_DESIGN.md).

## Выбор идентификатора

| Что адресуем | Идентификатор | Вид |
|--------------|---------------|-----|
| Пользователя | Username | `/users/{username}` |
| Созданное администраторами, таких десятки | Alias | `/forum/{alias}` |
| Созданное пользователями, число не ограничено | PublicId | `/game/{publicId}` |
| Живущее внутри родителя и не переносимое в другого | Numeric | `/forum/{alias}/{num}` |
| Одноразовую операцию по ссылке из письма | Token | `/activate#token={token}` |

Страница без сущности адресуется фиксированным путем без идентификатора (`/rules`, `/community`).

## Типы идентификаторов

### Username

Имя пользователя как есть, URL-кодированное: `Adam Advena` дает `/users/Adam%20Advena`. Поиск по адресу без учета регистра. Правила имени и регистра в [USERNAME_POLICY.md](USERNAME_POLICY.md).

### Alias

Строчная латиница, цифры и дефис, первой идет буква: `[a-z][a-z0-9-]*`. Уникален в пределах типа, поиск без учета регистра. Alias не меняется: на нем стоят ссылки, а перенаправления со старого значения нет. Пример: раздел форума `/forum/general`.

### PublicId

Строчные буквы из алфавита в 23 буквы (латиница без `i`, `l`, `o`, чтобы не путать с `1` и `0`), не короче пяти. Вычисляется из `SerialNumber` сущности в [PublicIdService.cs](../../src/DM.Domain.Core/Identity/PublicIdService.cs), поэтому уникален в пределах типа и не меняется.

PublicId последовательный: зная один, соседние получают перебором. Закрытость сущности держат права доступа, а не неизвестность адреса. Адреса вида `/game/{publicId}`, `/blogs/{publicId}`, `/messenger/c/{publicId}`.

### Numeric

Порядковый номер внутри родителя: натуральное число, уникальное в пределах родителя, неизменное. Номер удаленной записи не переиспользуется. Как выдавать номер без гонки, сказано в [PATTERNS.md](PATTERNS.md), в разделе про `MAX+1`.

Номер в адресе не равен месту в списке, место хранит отдельное поле (`OrderNumber` у игровой комнаты). Игровая комната, созданная третьей, остается `/rooms/3` и после перестановки в начало списка. На экране пользователь видит название, а не номер. Адреса вида `/game/{publicId}/rooms/{num}`, `/game/{publicId}/chat-rooms/{num}`.

### Token

Значение из письма идет во фрагменте `#token=`, а не в пути или query. Почему, сказано в [SECURITY.md](SECURITY.md#требования-к-токенам). Ссылку собирает `ConfirmationLink` в [AccountMailSender.cs](../../src/DM.Domain.Account/Features/Mail/AccountMailSender.cs), страница читает значение и стирает его из адреса через [confirmationToken.ts](../../src/DM.Web.Client/src/shared/lib/utils/confirmationToken.ts).

## Структура адреса

Вложенное продолжает путь родителя: `/{parent}/{parentId}/{child}/{childNum}`. Например, `/blogs/{publicId}/feed` это лента публикаций блога, и публикации вложены под ней.

Адрес по внутреннему идентификатору, на который ведет уведомление, это не страница, а переход: страница читает сущность и заменяет адрес каноническим. Так `/forum-topic/{topicId}` становится `/forum/{alias}/{num}`.

### Пагинация

Страница списка в адресе это `?number=N`, номер страницы, а не элемента. Первая страница пишется без параметра. API берет `skip` и `take`, номер в смещение переводит клиент ([API_DESIGN.md](API_DESIGN.md#словарь-query-параметров)).

### Фильтры и сортировка

Фильтр и сортировка живут в query, чтобы ссылка открывала тот же вид: `/games?status=Active&sortBy=title`, `/blogs/{publicId}/feed?rubric={rubricId}`.

- Значение по умолчанию в адрес не пишется.
- Несколько значений одного параметра идут через запятую: `requiredTags=a,b`.
- Неизвестное значение из адреса отбрасывается, страница открывается с умолчанием.

## Правила именования

| Правило | Пример |
|---------|--------|
| Путь строчными буквами | `/games`, не `/Games` |
| Список во множественном числе | `/games`, `/polls` |
| Элемент в единственном | `/game/{publicId}` |
| Составное слово через дефис | `/global-chat`, `/post-reviews` |
| Query-параметр в camelCase | `?sortBy=created`, `?recruitmentFilter=open` |

Исключения записаны: `/users/{username}` и `/blogs/{publicId}` берут множественное число и для элемента, путь элемента продолжает путь списка.
