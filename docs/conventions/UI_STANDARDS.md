# Стандарты UI-компонентов

Единые стандарты для типовых UI-паттернов. Single Source of Truth.

---

## Z-Index Scale

Централизованная шкала z-index для всех overlay-компонентов.

| Уровень | Значение | Компоненты |
|---------|----------|------------|
| Chat FAB | 10 | Кнопка прокрутки к последним сообщениям чата |
| Dropdown | 100 | Autocomplete, filter dropdowns |
| Sticky | 200 | Headers, sidebars |
| Drawer scrim | 900 | Выдвижная панель узкого экрана — затемнение |
| Drawer | 950 | Выдвижная панель узкого экрана |
| Dialog | 1000 | Dialog |
| Popover | 1100 | Popovers over dialogs |
| Tooltip | 9000 | Tooltips |
| Toast | 10000 | Notifications |

Drawer держится чуть ниже уровня диалога: диалог, открытый изнутри выдвижной панели (например, "Подписаться" из меню игры), должен перекрывать ее.

**Файл:** `src/DM.Web.Client/src/assets/styles/_ZIndex.sass`

## Брейкпоинты

Шкала breakpoint-токенов для layout-медиазапросов. Обязательна для нового кода: новый медиазапрос берет токен, а не литеральное значение; оставшиеся в старом коде литералы заменяются токеном при правке файла.

| Токен | Значение | Назначение |
|-------|----------|------------|
| `$bp-shell` | 1000px | Порог схлопывания 3-колоночного шелла, включительно: обе колонки уходят в одну выдвижную панель, меню и статистика шапки тоже (раздел "Телефон и выдвижная панель"). Столбик кнопок справа внизу с шестеренкой стоит на любой ширине, до порога в поле страницы |
| `$bp-tablet` | 768px | Граница телефона: устройство, у которого меньшая сторона экрана уже 768, раскладывает страницу шириной самого узкого шелла (раздел "Телефон и выдвижная панель") |

Ступеней уже `$bp-tablet` у раскладки нет: своей верстки у телефона нет, он показывает полную версию, и медиазапрос под ширину телефона новым кодом не заводится. Узкое правило, которое все же нужно, решает ширина своего блока (контейнерный запрос), а не окна.

**Файл:** `src/DM.Web.Client/src/assets/styles/_Breakpoints.sass` (глобально доступен через `additionalData` в `vite.config.ts`, как `Variables`/`Layout`/`Themes`).

## Шкала отступов

Отступы берутся из шкалы, литеральные пиксели запрещены. База 4px, дальше удвоением.
Обязательна для нового кода: новый отступ берет токен, а оставшиеся в старом коде
литералы заменяются токеном при правке файла. Отсюда же берется ответ на вопрос,
почему в разметке не встречаются 10px и 12px: таких ступеней в шкале нет.

| Токен | Значение |
|-------|----------|
| `$tiny` | 2px |
| `$minor` | 4px |
| `$small` | 8px |
| `$medium` | 16px |
| `$big` | 32px |
| `$major` | 64px |
| `$large` | 128px |

**Файл:** `src/DM.Web.Client/src/assets/styles/Variables.sass` (глобально доступен через `additionalData` в `vite.config.ts`).

## Dropdown/Filter Standards

| Параметр | Значение | Обоснование |
|----------|----------|-------------|
| Height (input) | 38px (`$control-height`) | Одна высота у всех контролов страницы. Поиск в строке фильтров и есть мера однострочного поля страницы: текст 14, отступ 8, заливка поля, рамка `$border`, скругление 8 |
| Min-width | 260px | Readable content |
| Max-height | 300px | Scrollable, не занимает весь экран |
| Avatar size | 24px, квадрат | Consistent in lists, картинки не скругляются |
| Debounce (search) | 300ms | Balance UX/performance |
| Debounce (URL sync) | 50ms | Batch rapid clicks |

Строка фильтров (поиск, "Фильтры", сортировка) стоит одной строкой на любой ширине, как на 1366, телефон тоже (`=filter-bar`). Только колонка, которой не хватает места на кнопки рядом с поиском (средняя колонка окна 1024), переносит то, что не поместилось, на следующую строку, и строка за колонку не выходит. Слово у кнопки стоит на любой ширине, значка вместо подписи нет, поля кнопок одни на любой ширине. У строки поиска чата свое правило (раздел "Ленты сообщений").

Строки модерации. "Все загруженные файлы", "Последние предупреждения", "Последние баны" и "Удаленные пользователи" ищут строкой поиска: поле поиска сайта (`FilterSearchInput`) на всю ширину колонки и "Найти" (главная) справа, обе 38, подписи над полем нет. Ищут "Найти" или Enter, а не по мере набора. Подсказка в поле называет, что ищется, и говорит "Точное" только там, где сервер сравнивает имя целиком ("Точное имя пользователя"); у удаленных пользователей совпадает часть имени или почты, там "Имя или почта". Опустевшее поле (крестик или стертый текст) снимает фильтр сразу, без "Найти". Имя живет в адресе, новое имя открывает список с первой страницы; имя, которого нет, дает "{Кого} по заданным фильтрам не найдено", а не ошибку загрузки. "Нарушители" фильтруются сегментами "Все | С баном | Только баллы". Очередь "Обращения" фильтруется двумя списками над очередью, "Тип обращения" ("Все типы" и причины, которые сервер показывает роли читателя) и "Статус" ("Все статусы" и четыре хранимых статуса раздела "Обращение"): выбор применяется сразу и живет в адресе (`?subtype`, `?status`).

**Файл:** `src/DM.Web.Client/src/assets/styles/_Filters.sass`

## Table UX Standards

| Требование | Реализация |
|------------|------------|
| Row hover | `background-color: $bg-element-hover` + transition 0.15s |
| Empty state | `EmptyState` или `SecondaryText` компонент |
| Нет значения в ячейке | Общий токен из констант интерфейсных строк, а не прочерк: в колонке чисел прочерк читается как ноль, а два разных знака "пусто" читатель учит дважды |
| Loading state | `DataTableSkeleton` — только когда данных еще нет, теми же столбцами, что таблица: ячейки скелетона стоят под заголовками настоящей таблицы, и столбцы не сдвигаются, когда приходят строки |
| Пустая таблица | Пришел ответ без строк: стоят все столбцы, строка пустоты идет через все столбцы и переносится только там, где ей не хватает ширины за своими полями |
| Перезагрузка | Уже показанные строки остаются видимыми (`aria-busy="true"` на таблице), skeleton их не заменяет |
| Сортировка | `aria-sort` на заголовке; первая сортировка колонки может задавать естественное направление (`defaultDirection`) |
| Virtual scroll | >50 элементов |
| Столбцы | Таблица стоит всеми своими столбцами на любой ширине окна, телефон тоже: столбцы не уходят, не складываются в строку под заголовком и не объединяются. Где таблице с целыми словами не хватает колонки, она остается шире колонки и листается вбок в своей рамке (`.data-table-scroll`, контейнер по ширине, поэтому ширина таблицы до предков не доходит), а страница не едет никогда. Слово в ячейке не рвется, чтобы влезть: разрыв резал название игры на "Королевс" и "тв". Таблица атрибутов листа (`AttributeSchemaEditor`) стоит всеми столбцами: "Название", "Тип", "Приватность", "Обязательность", "Дескриптор" и столбец карандаша и корзины. У ячеек боковое поле 4, чтобы шесть столбцов вставали без прокрутки в форму создания игры, в настройки игры и в шаблон на 1366 и на телефоне, где раскладка дает те же рамки. Где рамка уже наименьшей ширины таблицы (средняя из трех колонок в более узком окне, например на 1024), таблица листается вбок в своей рамке (`.table-wrap`, контейнер по ширине), как `DataTable`, а страница не едет |
| Ширины | Один резиновый столбец без ширины, остальные долями всей таблицы или в px; раскладка auto, ширины не переключаются по брейкпоинтам. Столбец начинается с объявленной ширины и не уже своего самого длинного слова. Где места хватает, доли стоят как объявлены, до пикселя |
| Перенос | Только между словами, после дефиса и косой черты; `hyphens: none`, слово внутри не рвется, логин тоже, что бы ни говорил о себе компонент в ячейке |
| Таблица сведений | Сведения под названием игры и блога (`+info-table`): подпись по своей ширине одной строкой на любой ширине, значение переносится между словами. Держит `infoTable.spec.ts` |
| Действие строки | В таблицах и плотных списках ссылкой ("Удалить" в загрузках модерации и в списках ролей игры и блога, "Отписаться" в подписках). Одно действие на одной странице называется одним словом. Кнопка 38 только в строках широких списков, где у действия есть место ("Завершить" у сессии аккаунта, "Принять" и "Отклонить" у приглашения): в таблице кнопка выше строки и шире своего столбца (решение владельца от 5 октября 2026) |
| Таблица с добавлением и удалением | Образец один, схема атрибутов, и по нему стоят черные списки игры, блога и аккаунта, тиры достижений и серии конкурсов. Правка строки карандашом, удаление корзиной в самой строке (`RowIconButton`, `shared/ui/RowIconButton`), у значка имя для читалки ("Удалить TestUser из черного списка", "Редактировать тир X"). Добавление стоит под таблицей: у черного списка строка с полем поиска пользователя и "Добавить" сразу под рамкой таблицы, видом ее последней строки (та же рамка, поля ячейки и фон подвала, окна нет), у остальных кнопка под таблицей ("+ Новый атрибут", "+ Тир", "+ Новая серия"). Новая запись встает туда, куда ее ставит порядок сервера: в черном списке игры и блога последней, в черном списке аккаунта первой. Корзина черного списка и строки схемы, которая уйдет только с сохранением формы, ничего не спрашивает, остальные удаления спрашивают окном. Действие, которое не удаляет ("Скрыть" и "Вернуть" серии), остается словом |
| Раскрывающийся список со столбцами | `ExpandableList` с `columns` держит то же правило: столбец без ширины в px не уже самого длинного слова; несколько таких столбцов сначала получают по своему слову, а остаток делят поровну. Где места мало, список листается вбок в своей рамке, как таблица, а раскрытый текст строки стоит по ширине рамки и не уезжает вместе со строкой. В списке, где в строках ссылки (`plainRows`), строку раскрывает треугольник-кнопка; строка, которой нечего раскрывать, стоит обычной строкой таблицы, без треугольника. Так сделана таблица администрации на правилах: "Роль", "Функции" и "Состав" на любой ширине, логины целиком и без подсказки |

Держат `DataTable.spec.ts` (столбцы, рамка, подвал, любая ширина), `infoTable.spec.ts` и e2e `common/tables-fit.spec.ts`; таблицу топиков раздела e2e `forum/topics-table-fit.spec.ts`, столбцы `/games` e2e `gaming/games-list.spec.ts`, шесть столбцов схемы атрибутов e2e `gaming/attribute-schema-columns.spec.ts`, черные списки `BlacklistEditor.spec.ts` и e2e `personal/blacklist-look.spec.ts`.

**Файл:** `src/DM.Web.Client/src/assets/styles/_Tables.sass`

## Dialog Standards

**Словарь:** модальное окно называется **dialog**. Конкретные модалки называются `*Dialog`. Термины "Modal"/"Lightbox" в именах и копиях не используются.

**Два яруса, и выбор между ними не свободный.** Диалог с формой, который открывается из кода и возвращает результат, берет общий примитив `Dialog` поверх vue-final-modal. Диалог-примитив дизайн-системы, который встраивается в разметку потребителя (подтверждение, ввод одного значения), собирается на Teleport и обязан брать поведение оболочки из общего композабла, а не писать его заново: именно так два таких диалога разошлись, и один остался без ловушки фокуса.

Новый самокатный оверлей заводить нельзя. Требования ниже — не пожелания, а то, что оболочка дает по построению.

| Требование | Реализация |
|------------|------------|
| role | `role="dialog"`, у подтверждения `role="alertdialog"` |
| aria-modal | `aria-modal="true"` |
| Focus trap | Фокус внутри диалога. Диалог, который открывается изнутри окна (вопрос над окном), стоит в разметке этого окна, а не в `body`: ловушка окна забирает фокус у всего, что вне него |
| ESC | Закрытие по Escape, если окно не ждет ответа и не держит набранный текст (ниже). Контрол внутри окна, который забирает Escape себе (вопрос над окном, календарь поля даты, открытые подсказки имен), останавливает его всплытие, и до окна такой Escape не доходит. Отмену действия по умолчанию (`preventDefault`) окно за такой знак не считает: редактор разметки гасит так каждый Escape, и окно с ним не закрывалось бы вовсе |
| Click-outside | Закрытие по клику мимо карточки, когда и нажатие, и отпускание пришлись мимо нее. Выделение, протянутое из карточки наружу, окно не закрывает |
| Focus restore | Возврат фокуса на trigger |
| Страница под окном | Заперта и не сдвигается вбок: контейнер прокрутки `.main` получает `overflow: hidden` вместе с `scrollbar-gutter: stable`, место полосы прокрутки остается за ней (`usePageScrollLock`) |

**Подпись кнопки закрытия — "Отмена".** Это существительное: кнопка не выполняет
действие, а уходит из формы, ничего не сделав. "Отменить" остается только там, где
кнопка действительно отменяет уже совершенное — снимает голос, отзывает
приглашение, — и тогда за глаголом идет дополнение: "Отменить голос".

**У гостевых поверхностей "Отмены" нет вовсе.** Вход, регистрация,
восстановление доступа и остальные гостевые формы открываются в `AuthDialog`,
и выход из них один: крестик в углу карточки (`aria-label="Закрыть"`), Escape
и клик мимо. Довод в том, что у гостевой карточки ровно одно действие и оно
названо результатом ("Создать аккаунт", "Отправить письмо"): "Отмена" рядом с
ним ничего не отменяет, а только уходит с формы, и вторая кнопка спорила бы с
главной за внимание, ничего к ней не добавляя. Крестик говорит то же самое, не
занимая строки, и рисуется перекладинами, а не печатается знаком шрифта.

На страницах, открытых по ссылке из письма, крестика нет: там нечего
закрывать, поверхность и есть страница.

**Окна сайта держат "Отмену" рядом с крестиком.** Окно с формой и окно
подтверждения меняют данные, часто чужие, и отход из них должен быть виден
кнопкой, а не только угадан по крестику. Поэтому в ряду две равные кнопки:
первая делает дело, вторая "Отмена". Правило ниже про одну кнопку относится
только к гостевым поверхностям.

**Вид окна сайта.** Карточка берет у гостевой поверхности то, чего сайту не
хватало: фон страницы без рамки и тени, крупные поля, крестик в углу. Все
остальное остается сайтом: заголовок стилем заголовков сайта (у формы слева, у
подтверждения по центру), кнопки сайта в ряд равными половинами, вровень по
высоте с полями, с подписью 16, как у гостевой кнопки. Красным опасное
действие не метится: опасность несут слова заголовка и текста. Окно шире, если
внутри редактор, чтобы его панель вставала в одну строку.

**Окно само ведет свой запрос.** Окно, которое меняет что-то на сервере,
получает действие (`action`): функцию, которая возвращает ответ клиента
`{ data, error }` или ничего, если сервер не спрашивается. Окно запускает ее
главной кнопкой, само показывает ожидание и отказ и закрывается только после
успеха. Вызывающий экран окно по успеху не закрывает и отказ из окна не
показывает. Запрос из окна несет флаги `ownsRefusal` и `ownsRateLimit`: отказ
печатает окно, и перехватчик о нем молчит (раздел "Всплывающие сообщения").

**Отказ стоит в окне, над кнопками.** Отказ шага печатается красной строкой 14
над рядом кнопок, несет `role="alert"` и места заранее не держит: окно без
отказа стоит как стояло, а пришедшая строка растит карточку и отодвигает ряд от
тела. Карточка, которая помещается в рамку, стоит по ее центру и растет в обе
стороны: тело поднимается, а ряд опускается, каждый на половину прибавки.
Карточка выше рамки стоит от ее верха, и ряд опускается на всю прибавку. Отказ по полю
(код валидации) встает под этим полем, если поле назвало окну свое серверное
имя (`FormField` со свойством `field`), и в строку тогда не идет. Когда сервер
ничего не сказал, строка говорит фразу окна (`failure`). 429 встает в ту же
строку фразой с обратным отсчетом, и главная кнопка заперта до нуля. Отказ без
ответа (статус 0) окно не печатает, о нем говорит перехватчик. Исключение,
брошенное действием, считается отказом, и окно отпирается. Красного на кнопках
окна нет и тут: красная только строка отказа и строка под полем.

**Во время запроса окно заперто.** Главная кнопка заштрихована, как всякий
запертый контрол сайта, и несет `aria-busy`. "Отмена" погашена. Крестик
тускнеет и несет `aria-disabled`, а не атрибут `disabled`: на нем ждет фокус,
пока нажатая кнопка отключена, и возвращается на нее после ответа. Escape, клик
мимо и ссылки в карточке до ответа не работают. Второе нажатие второго запроса
не шлет.

**Окно остается окном.** Форма, которую открывают кнопкой, открывается окном
`Dialog`, вопрос перед действием открывается окном `ConfirmDialog`. Форму и
вопрос на страницу вместо окна не переносят. Без окна делается три дела:
вставка ссылки, картинки, подписи спойлера и читателей скрытого текста в
редакторе открывается панелью `InsertPanel` под нажатой кнопкой (окно для
нее владелец назвал слишком навязчивым), порядок закрепленных топиков меняют
перетаскиванием закрепленного топика за значок в самом списке топиков, а имя в
черный список игры, блога и аккаунта вносят строкой под его таблицей, видом ее
последней строки: поле "Имя пользователя" и "Добавить" (`BlacklistAddRow`),
отказ строкой под ними (раздел "Table UX Standards", строка "Таблица с
добавлением и удалением"). Без вопроса выполняется только черный список и
строка схемы атрибутов, которая уйдет с сохранением формы: имя возвращается тем
же полем, строка уходит на глазах. Любое другое удаление спрашивает окном.

**После успеха окно закрывается.** Если результат виден на странице сразу
(список обновился, запись появилась, статус сменился), плашки об успехе нет:
ответом служит сама страница за закрытым окном. Если на странице от действия не
меняется ничего, окно после закрытия говорит об успехе плашкой, и эта плашка
записана в реестре (раздел "Всплывающие сообщения"). Отказ окно не закрывает.

**Набранный текст защищен вопросом.** Окно, в котором набран многострочный
текст, объявляет себя грязным (`dirty`). Клик мимо такое окно не закрывает, а
Escape, крестик и "Отмена" открывают поверх него вопрос "Закрыть без
сохранения?" с одним предложением о том, что пропадет, и кнопками "Закрыть" и
"Отмена". Вопрос не задается, когда окно закрывается после успеха и когда
истекла сессия: отправить набранное уже не с чем. Однострочные и гостевые формы
грязными себя не объявляют, потеря одной строки дешевле второго окна.

**Конец сессии закрывает окна.** Когда сайт узнает, что сессия кончилась, он
закрывает все открытые окна, кроме окна входа, и только потом ведет на вход:
форма, которую уже нечем отправить, над окном входа не остается (реестр
открытых окон `useOpenWindows`, гостевые окна в него не входят).

**Начальный фокус.** В подтверждении фокус стоит на "Отмене": Enter, нажатый
не глядя, уводит из окна, а не выполняет действие. Признака опасности, который
переставлял бы фокус, у подтверждения нет. В окне с формой фокус встает в
первое пустое поле, если пустых нет, в первое поле, если полей нет, на крестик.
Фокус ставится без прокрутки. Своего обработчика Enter окно не ставит: Enter из
однострочного поля отправляет форму сам, а кнопка с фокусом нажимается сама.

**Высокое окно прокручивается целиком.** Карточка выше экрана начинается от его
верхнего края и прокручивается вся, вместе с крестиком и кнопками. Липкого в
карточке нет ничего: липкий ряд кнопок закрывал бы поле с фокусом.

**Правило выходов гостевой поверхности.** Оно одно на обе гостевые поверхности
и читается по тому, есть ли на карточке крестик.

В диалоге выход дает крестик, и то же самое делают Escape и клик мимо карточки.
Кнопка появляется только тогда, когда на карточке есть что сделать, и называется
этим делом: "Создать аккаунт", "Отправить письмо", "Попробовать другую почту".
Кнопка, которая только закрывает, запрещена: она повторяет крестик, занимает
строку и встает на место главного действия, так что читатель сравнивает две
кнопки одного размера. Карточке, у которой дела не осталось, кнопка не нужна
вовсе: квитанция "Проверьте почту" закрывается крестиком.

На странице из письма крестика нет, поэтому каждое состояние, которое уже
ответило, несет выход кнопкой и называет, куда она ведет: "Войти", "На главную",
"Перейти в профиль".

Три края, которые правило проходит:

- **Кнопки нет вовсе.** В диалоге это норма: выход дает крестик. На странице из
  письма не норма, там кнопка и есть единственный выход.
- **Два выхода на одной карточке.** Допустимо, если это разные вещи: крестик
  уходит ни с чем, кнопка ведет дальше. Две кнопки рядом это уже не выходы, а
  выбор, и он делается по общему правилу главного действия.
- **Ожидание.** Состояние, которое еще не ответило ("Проверяем ссылку..."),
  выхода не несет: уходить не из чего, ответ придет сам.

**Гейт:** `src/DM.Web.Client/src/guestSurface.spec.ts`, "the way out of a guest
card" — падает на вернувшейся кнопке "Закрыть".

## Телефон и выдвижная панель

Телефон показывает полную версию, как DM2: отдельной раскладки у него нет. Устройство, у которого меньшая сторона экрана уже 768 (`$bp-tablet`), раскладывает страницу шириной 706, браузер ее уменьшает, а читатель приближает (скрипт в `index.html` ставит `<meta name="viewport" content="width=706">`, планшет и компьютер оставляют ширину устройства). 706 это самая узкая раскладка шелла, у которой средняя колонка не уже средней колонки 1366 (642): поэтому страница на телефоне выглядит как средняя колонка той же страницы на 1366, ничего не вылезает за край и не прячется. Решает экран, а не окно, и поворот телефона раскладку не меняет. Корень приложения не уже 706 (`$narrowest-layout` в `App.vue`), и окно браузера уже этого листает страницу вбок. `text-size-adjust: 100%` не дает телефону укрупнять текст абзацев и ломать строки там, где их не ломает раскладка. Числа `index.html` и `App.vue` сверяет `phoneLayout.spec.ts`.

Раскладка телефона та же, что у окна 768-1000: на 1000 и уже (`$bp-shell` включительно) обе колонки шелла, меню и статистика шапки уходят в одну выдвижную панель. Это те же колонки, что на компьютере, а не копии: они грузятся со страницей, их прокрутка и свернутые блоки сохраняются между открытиями.

| Требование | Реализация |
|------------|------------|
| Компонент | `MobileDrawer` (`shared/ui/Drawer`): рамка, в которую `App.vue` кладет оба вида. Без Teleport, `position: fixed` у левого края, ширина `min(85vw, 600px)` |
| Режим ширины | `useShellMode()` (`shared/lib/composables`) отвечает одно: `narrow`, окно 1000 и уже. Число то же, что в `_Breakpoints.sass`, `useShellMode.spec.ts` их сверяет. Режима телефона нет |
| Кнопка | Одна, в шапке у левого края (раздел "Шапка"). Открывает панель на виде "Меню" |
| Виды | В полосе панели вкладки сайта "Меню" и "О сайте" (`Tabs`, вид заголовков), открытая стоит первой. "Меню": меню разделов шапки (`MainMenu`, тот же компонент и вид, что в шапке 1366, по левому краю), затем левая колонка. "О сайте": статистика шапки (`SiteStatistics`, тем же видом), затем правая колонка целиком, последним блоком "Правовая информация" (`LegalLinks`: пользовательское соглашение и политика конфиденциальности). Под меню и под статистикой отступ 32. Блоки колонок стоят видом полной версии, своих строк у панели нет. Настроек сайта в панели нет, они у шестеренки столбика кнопок на любой ширине |
| Состояние | `useUiStore().openedPanel` (`null`, `"left"`, `"right"`) с `openPanel`, `closePanel`, `togglePanel`: поле называет открытый вид. Оба вида смонтированы всегда, каждый помнит свою прокрутку: вид, который еще не открывали, начинается сверху, остальные возвращаются туда, где их оставили |
| Страница из письма | Шире 1000 колонок нет. На 1000 и уже в панели только меню и статистика |
| Полоса панели | Вверху полоса 52: вкладки видов от поля 16, крестик окна (`+dialog-close`) в правом углу, под полосой черта 1px `$border`. Содержимое прокручивается под чертой. Затемнение `$overlay-bg` без размытия, как у окон |
| Открытая панель | Модальное окно: `role="dialog"`, `aria-modal`, имя "Меню", как у кнопки, фокус на крестик и обратно на кнопку (`useDialogShell`), шапка, `main` и футер `inert`, страница держится `usePageScrollLock`, прокрутка панели не перетекает (`overscroll-behavior: contain`). Закрытая панель `inert` и `visibility: hidden` |
| Закрытие | Крестик окна в правом углу полосы, нажатие на затемнение, Escape, нажатие любой ссылки внутри (в том числе на открытую страницу), смена адреса, расширение окна шире 1000, жест "назад" Android через `CloseWatcher`, где он есть. Записей в историю не добавляется |
| Анимация | Выезд 0,25 с по `transform`; при `prefers-reduced-motion` сразу |

Над футером блоков нет ни на какой ширине: конец правой колонки (обратная связь, поддержка проекта, партнеры и соцсети, `RightSidebarTail`) стоит в самой колонке, а до 1000 в виде "О сайте" панели.

Шире 1000 колонки стоят на странице. У страницы, которая правого вида не объявляет (комната постов, переписка), правой колонки нет вовсе, и средняя колонка берет ее ширину, как на DM2.

Знак сворачивания блока колонки, здесь и на компьютере, это плюс 10 цветом `$heading-alt`: у свернутого блока плюс, у раскрытого он повернут на 45 в крестик. Под указателем знак виден при наведении на заголовок блока и при фокусе, на касании виден всегда с прозрачностью 0.4. Держит `SidebarBlock.spec.ts`.

## Страница не шире окна

Средняя колонка берет ширину, которую ей оставил шелл (`min-width: 0` в `App.vue`), а страница укладывается в нее сама, теми же правилами, что на 1366. На 1001-1279 шелл стоит в три колонки, и средняя колонка там вдвое уже, чем на 1366: строка переносится, ряд кнопок переносит кнопки на следующую строку (раздел "Ряд целиком"), строка фильтров переносит кнопки под поиск, сетка карточек ставит в ряд столько карточек, сколько вмещает ее блок, а таблица, которой не хватает колонки, листается в своей рамке (раздел "Table UX Standards"). Телефон рисует колонку 1366, поэтому на нем страница стоит так же, как на 1366.

Доски лидеров (статистика и итоги периода в топике и на главной) стоят по одной, по две или по три в ряд. Доска не уже 11.5em: на ее строке помещается логин в 20 латинских букв с отступами 16. Колонки равные и не шире сетки, имя длиннее целой строки доски переносится у ее края, как логин в тексте. Решает ширина блока досок (контейнер `stat-boards`): на 1366 и на телефоне три в ряд.

Держат `PeriodDigestBoards.spec.ts`, `SiteStatisticsPage.spec.ts`, `StatBoard.spec.ts` и e2e `common/page-width.spec.ts`: документ и шелл не едут вбок, правая колонка шире 1000 в окне, ни одна часть средней колонки не выходит за ее края, кроме того, что держит своя рамка с прокруткой.

## Шапка

Шапка стоит на бумажной полосе с рваным краем внизу. Полоса это фон самой шапки (`widgets/header/Header.vue`, `::before`) во всю ее высоту: картинка высотой 100 нарисована дважды, внизу с рваным краем и вверху для остальной высоты, где видна только ровная бумага. Поэтому край на любой высоте шапки тот же, что на 1366, и не растягивается. Шапка 100 на любой ширине; длинное приветствие до 1000 добавляет ей строку.

| Ширина | Шапка |
|--------|-------|
| Шире 1000 | Слева логотип и приветствие, справа статистика, обе колонки по 330, как колонки страницы. Меню разделов между ними по левому краю, на линии текста страницы, как меню DM2 сразу за логотипом, по середине шапки по вертикали, межбуквенный 1. Шрифт самый крупный, при котором меню встает в две строки: ступени 25, 20, 17, 15 по ширине окна, у девяти пунктов модератора раньше. Шрифта меньше 15 нет: где и на 15 две строки не держат (девять пунктов у самого порога), меню берет третью строку той же ступени. На ступени 15 боковое поле меню 16 вместо 32, и меню начинается на 16 левее линии текста |
| 1000 и уже | Одна кнопка 44 на 44 у левого края, в 8 от него, по середине блока логотипа и приветствия. Логотип по центру экрана, под ним по центру приветствие. Меню и статистики в шапке нет: они первыми стоят в видах выдвижной панели |

Ступень выбирает ширина окна в стилях (`+menu-steps` в `Header.vue`), замера нет. Пункт меню не рвется внутри себя, меню переносится только между пунктами. Ссылки меню рисует `widgets/header/MainMenu.vue`, шапка задает им ступень. Держат `menuSteps.spec.ts`, `headerLook.spec.ts` и e2e `common/one-line.spec.ts`, блок "The menu of the header".

Приветствие стоит по центру рисунка логотипа и не ближе 16 к краю экрана: длинная строка сдвигается от края, а не уходит за него. Логин не режется: влезающая строка стоит одной строкой там же, где стояла, а длинная (логин из 20 широких букв) держится шириной своего ящика и переносится между словами, шапка растет на строку; слово шире ящика ломается у его края. Числа "(0/4)" палец находит по полю касания 24 на 32 у каждого, поверх строки: первое тянется влево через скобку, второе вправо через скобку и черту, встречаются в середине косой черты. Квадратов с конвертом и колокольчиком нет ни на одной ширине.

Знак кнопки это три полосы, выведенные из значка верстки "Компактная" настроек сайта (`menu` рядом с `layoutCompact` в `icons.ts`), 22 в ширину, цветом текста, как логотип рядом, при наведении `$link-hover`. Подсказка "Меню" по наведению и фокусу, на касании не всплывает. `aria-haspopup="dialog"`, `aria-expanded` по открытой панели.

Строка статистики переносится только после запятой, второе число целиком. Ноль прироста и онлайн, равный нулю, серые, больше нуля зеленые: зеленый значит рост, а не число.

## Низ страницы

Футер на любой ширине полный, как на 1366: знак "18+", авторы, пользовательское соглашение и политика конфиденциальности. Его бумажная полоса рисуется двумя слоями одной картинки: сверху картинка высотой 150 с рваным краем, под ней та же картинка во всю высоту футера, от которой видна ровная бумага. Поэтому край там, где футер выше, той же высоты, что на 1366, и без шва. Над футером блоков нет (раздел "Телефон и выдвижная панель").

Столбик кнопок справа внизу (`ScrollNav`: "Развернуть все", "Наверх", "Вниз", шестеренка "Настройки сайта") стоит на любой ширине всегда: не тает, не уходит при фокусе в поле и при открытой панели лежит под ее затемнением. Шестеренка открывает пузырь настроек сайта (`SiteSettingsPanel`: верстка, тема, перенос слов) на любой ширине; пузырь не выходит за окно и закрывается нажатием мимо и Escape. Шире 1000 столбик стоит в 16 от края окна, на 1000 и уже в поле страницы: в 4 от края области страницы, то есть от края окна на телефоне и от полосы прокрутки там, где она нарисована (столбик меряет ее сам, `--page-scrollbar`), так что текста и карточек он не касается. Держат `ScrollNav.spec.ts`, `Footer.spec.ts`, e2e `common/phone-bottom.spec.ts` и `common/settings-panel.spec.ts`.

## Button/Control States

Стандарт владельца от 28 сентября 2026: мера страницы это строка фильтров списка игр, какой она была до 27 сентября (поиск, "Фильтры", сортировка), и по ней нарисованы все кнопки и однострочные поля страницы. Высота 32, введенная 27 сентября, отменена. Окно держит свою высоту 52, многострочное поле растет строками; все остальное у контролов общее. Окна описаны в разделе "Dialog Standards" и здесь не пересматриваются.

| Требование | Реализация |
|------------|------------|
| Высота на странице | 38 (`$control-height`) у однострочного поля, списка, поиска в строке фильтров, поля даты, триггера даты и месяца, сегментов и любой кнопки: обычной, главной, в строке списка. Поле берет высоту объявлением в `+input`, а не из отступов и строки шрифта, поэтому поле и кнопка в одном ряду стоят вровень при любом шрифте. Многострочное поле (редактор разметки, текст подсказки, большой текст) держит свои отступы и растет строками. Поля в панелях фильтров и дропдаунов (поиск тега, даты, числа) той же высоты 38 и с тем же отступом текста, вровень с кнопками панели: своей меры у панели нет |
| Высота в окне | 52 (`$dialog-control-height`) у поля и у обеих кнопок, как утверждено для окон и гостевой карточки |
| Текст и отступы | Один размер у подписи кнопки и у текста однострочного поля: 14 (`$control-font-size`), у главной кнопки жирный. Текст поля начинается в 8 от рамки (`$field-inset`), боковой отступ кнопки 16 (`$button-padding`). Многострочное поле пишет 16, окно 15. ## Surface Standards

| Требование | Реализация |
|------------|------------|
| Карточка, строка списка, блок-ответ | `+card()`: рамка, отступ, фон, прямые углы |
| Нестандартный отступ | `+card($small)` — параметр, а не переписанный рецепт |
| Гостевой экран | `.auth-surface` — готовые классы листа `AuthSurface.sass` |

Рецепт поверхности не переписывается руками: разошедшиеся копии — это разошедшийся
дизайн.

Карточка контента скругления не несет (стандарт владельца от 27 сентября 2026):
скругленный угол это знак контрола, который человек нажимает, а блок с текстом
им не является. Это касается и миксина, и своих правил: секции настроек,
формы создания, строки комнат, превью чатов, панели ошибок, скелетоны этих
карточек. Скругление остается у контролов, у панелей дропдаунов и подсказок и у
карточки окна. Держит гейт `styleSystem.spec.ts`: `+card` не дает радиуса, и
блок, который его берет, не добавляет своего. Плавающие панели (дропдауны, поповеры) — отдельное семейство со своей
связкой позиционирования, тени и `z-index`: у них свой миксин в `_Filters.sass`.

Третье семейство — гостевая поверхность `.auth-surface`. На ней стоит все, что
человек видит, пока аккаунта у него нет: гостевые диалоги (`AuthDialog`) и
страницы, открытые по ссылке из письма. От карточки она отличается не оттенком,
а масштабом и ритмом:

- контролы крупнее общесайтовых: их на экране три-четыре, и они и есть вся
  страница;
- заголовок карточки ярусом крупнее заголовка диалога, капсом и по центру:
  карточка называет себя сама, заголовка страницы над ней нет;
- под каждым полем полоса под сообщение: ошибка, подсказка и оценка пароля
  встают в нее, и карточка не меняет высоту, когда приходит ответ сервера;
- главное действие одной кнопкой, названной результатом ("Создать аккаунт",
  "Отправить письмо"); второй кнопки рядом нет;
- страницы, на которые ведут ссылки из писем, говорят на том же языке, только
  карточка на них в рамке, а крестика нет.

Письмо это та же гостевая карточка, прочитанная в почтовом ящике: светлая тема
сайта (текст, приглушенный текст, заголовок, ссылка, линия, страница),
заголовок капсом и по центру, одно действие залитой кнопкой во всю колонку,
подпись под чертой, и все по центру, как на карточке-статусе. Лист сайта в
письмо не попадает, поэтому значения темы скопированы в константы стилей
письма (`EmailConstants`), а равенство копии и источника держит гейт
`EmailThemeShould`: переименованный или перекрашенный токен падает на стороне
письма, которую никто не открывает посмотреть. Шрифт письмо не загружает:
письмо, которое тянет шрифт с сайта, сообщает об открытии так же, как сообщил
бы логотип по ссылке.

Когда полоса краснеет:

- красное загорается, когда человек закончил с полем: ушел из него или нажал
  кнопку. Во время набора поле не краснеет, потому что требование, которое еще
  не успели выполнить, это не нарушение;
- гаснет на первом знаке в том поле, к которому относится, и возвращается тем
  же триггером. Уход из поля тоже стирает сообщение;
- стоит в полосе под тем полем, о котором говорит. Отказ по всему шагу занимает
  ту же полосу: у карточки одно место для сообщения, второе место было бы
  вторым правилом;
- шкала силы пароля из правила выведена: ее строка это правило и оценка, а не
  отказ, и она видна на пустом поле. Красной она становится, только когда
  сервер отказал самому паролю, и тогда краснеет вся полоса шкалы.

Числа языка живут в самом листе и в утвержденном прототипе, а не здесь: здесь
правило и довод, иначе документ разойдется с экраном на первой правке.

Рецепт лежит листом, а не миксинами: эти экраны рисуют одни и те же несколько
форм, и миксин выводил бы их заново в каждый scoped-блок, который его
импортирует. Руками он не переписывается по той же причине, что и карточка:
копия расходится с оригиналом на первой же правке.

**Файлы:** `src/DM.Web.Client/src/assets/styles/_Surfaces.sass` (глобально доступен через `additionalData`
в `vite.config.ts`, как `Variables`/`Layout`/`Themes`); `src/DM.Web.Client/src/assets/styles/AuthSurface.sass`
(подключается один раз из `app/main.ts` — он не миксины, а правила).

## Цветной край с одной стороны

Полоса цвета вдоль одной стороны на сайте значит ровно две вещи, и обе живут в
разметке постов: цитата и блок `[mod]`. Больше ее нет нигде.

Вид панели называют подложка-подсветка (`$bg-highlight-*`) и рамка целиком, в
тоне этого же цвета (`$border-accent-*`, а где его нет - `$accent-*`).
Состояние "сюда пришли по ссылке" называет подсветка, которая гаснет:
`.highlight-unread` в `Reset.sass`.

Довод: цветной край рядом с рамкой читается как вторая, конкурирующая рамка, и
метка цитаты теряет значение, когда ее носят шесть других мест. Серый
разделитель краем в этом смысле не считается - речь про цвет.

Держит гейт `styleSystem.spec.ts`, раздел "a coloured edge down one side": он
читает `border-left/right/top/bottom` и односторонние `inset`-тени во всех
стилях клиента, кроме `_BbcodeContent.sass`.

| Блок "пунктир + пагинация + пунктир" | `PagingWithSeparators`; отступ до соседнего контента — фиксированный `$medium` |
| Вид строки | "<< ... 4 5 6 ... >>": первая страница, шаг назад за окно, номера вокруг текущей, шаг вперед, последняя. Многоточия и переходы стоят на любой ширине (владелец, 5 октября 2026: если не помещается, меньше номеров, а не без многоточий). Список из десяти страниц и меньше, который помещается целиком, стоит без переходов |
| Число номеров | Сколько помещается в одну строку, от трех до десяти. `Paging` меряет ширину своей строки и подписи в шрифте сайта и считает окно (`pagesThatFit` в `pageWindow.ts`), заново при смене ширины, при загрузке шрифта и когда у номеров прибавляется цифра. Числа держит `Paging.spec.ts`: на 1366 десять трехзначных, на короткой строке три с многоточиями, в одну строку |
| Под таблицей | Строка стоит под видимой частью таблицы, а не под всей: таблица, которой не хватает колонки, листается в своей рамке, а подвал держится у ее левого края шириной с рамку (`DataTable`, `.table-footer-line`). Иначе ">>" уходил за край, пока таблицу не прокрутят |
| Ссылка | Боковое поле 8 на любой ширине (`--paging-side` в `_Paging.sass`), строку `Paging` меряет с ним же |
| Вертикальная центровка цифр | Оптическая (по чернилам глифов, не по line box) — компенсация живет в `PagingWithSeparators` |

## Навигационные полосы

Навигационные полосы (вкладки профиля и другие ряды ссылок внутри страницы) едины по всему сайту: компактный левый ряд, разделитель " | " реальными текстовыми узлами (копируется "О себе | Игры | Блоги | ..."), без тултипов. Пункты — обычные ссылки: $link, hover — $link-hover с подчеркиванием; активный — $link + вес (подчеркивание только на hover). "·" запрещен. Табы, живущие на одной странице (ЛК), выносят активный первым с FLIP-анимацией свапа; полосы-ссылки между страницами держат стабильный порядок. На узкой ширине полоса подчиняется правилу ниже. Разделы модерации полосой над содержимым не рисуются: это меню левого сайдбара (раздел "Меню левого сайдбара"). Разделы форума это полоса под заголовком "Форум" на разделе и на топике (`pages/forum/BoardNavigation.vue`, копируется "Общий | Игровые системы | ..."): в отличие от других полос-ссылок текущий раздел стоит первым и жирным, при переходе пункты переставляются FLIP-анимацией, потому что оболочка форума живет между переходами и перестановку видно. Полоса переносится как текст на любой ширине, вбок не листается; раздел и черта после него неразрывны, поэтому черта закрывает строку и никогда ее не открывает.

## Меню левого сайдбара

На страницах игры, блога и модерации их меню стоит первым блоком левого сайдбара, а полосы разделов над содержимым нет. Заголовок страницы называет место: игру, блог, раздел модерации словами его строки меню ("ИГРОВЫЕ ТЕГИ"). У форума меню в колонке нет: на всех его страницах заголовок "ФОРУМ", а разделы дает полоса под ним (раздел "Навигационные полосы"). Блок "Форум" закрывает левую колонку на всех страницах, форума тоже, и текущего раздела не выделяет.

Строка меню это "- " и ссылка, счетчик "(N)" серым после нее, копируется "- Общий (2)". В меню модерации строку рисует `shared/ui/MenuLink`. Он же ставит текущему пункту жирность и `aria-current`, а строка, которую текущей не назвали, и сама себя текущей не называет. Router-link без этого метит "page" любую ссылку на открытую страницу, в том числе число непрочитанных рядом с названием раздела. В меню модерации текущий пункт жирный цветом ссылки, но только там, где его называет сам адрес, по имени маршрута. Вложенные страницы (серия конкурсов, каталог типов наград, шаблон схемы, обращение) в меню ничего не выделяют, место называет заголовок. В меню игры и блога и в блоке "Форум" текущий пункт не выделяется.

Состав, подписи и права меню модерации берет одна таблица `shared/config/moderationSections.ts`: из нее же заголовок и вкладка браузера раздела и проверка роли. Меню стоит четырьмя группами без подзаголовков. Первая: "Премодерируемые игры", "Премодерируемые блоги", "Запросы на смену имени", "Обращения". Вторая: "Новые пользователи", "Удаленные пользователи", "Нарушители", "Модераторы". Третья: "Последние оцененные посты", "Последние предупреждения", "Последние баны", "Все загруженные файлы". Четвертая: "Игровые теги", "Шаблоны схем атрибутов", "Достижения", "Награды". У администратора последней отдельной группой стоит "Сбор средств". Группы разделены пустой строкой высотой строки меню, как группы меню игры на DM2. Порядок групп и подписи задает та же таблица (`MODERATION_GROUPS`). Группа, в которой у читателя нет ни одной видимой строки, не рисуется и пустой строки не оставляет: модератор видит три группы, без группы тегов, шаблонов, достижений и наград. Раздела, который читателю не открыт, в меню нет, а по прямому адресу оболочка зоны (`pages/moderation/ModerationPage.vue`) отвечает страницей 403 сайта во весь экран, без строки отказа под чужим заголовком. `/moderation` открывает "Модераторов", раздел, открытый любому модератору, хотя первой строкой меню они больше не стоят; туда же ведет пункт "Модерация" шапки. Держит `ModerationPanel.spec.ts`.

## Ряд целиком

Ничего не прячется и не режется из-за ширины: ни "Еще", ни "…", ни срезанного имени, ни прокрутки ряда вбок. Телефон показывает ряд полной версии (раздел "Телефон и выдвижная панель"), и своих перестроек у ряда для него нет: ни кнопок столбцом, ни поиска своей строкой, ни ушедших столбцов. Где ряду не хватает своей колонки (средняя колонка окна 1001-1279), он переносится, как текст. Ряд это любая строка из нескольких частей: подпись под содержимым, строка сведений, вкладки, ряд кнопок, строка фильтров и поиска.

1. Подпись под содержимым (`shared/ui/CaptionLine`) переносится только между частями. Часть стоит одной коробкой: не поместившаяся в остаток строки уходит на следующую строку целиком, а часть шире всей строки переносится внутри себя и не шире строки, слово длиннее строки ломается по базовому правилу сайта. Между частями стоит промежуток шириной " | " с чертой поверх, и на разрыве строки черты не видно: строка не начинается и не кончается чертой. Запятая между автором и датой (`<CaptionPart joint=",">`) стоит в конце своей части. Название после тире списка, которое продолжает предложение строки, переносится как текст (`<CaptionPart flow>`). Дата со временем одна часть. Копируется подпись одной строкой, как видна.
2. Шапка комментария: имя, буква роли и [offline] или [online] стоят частями через пробел строки и переносятся, как части подписи. Шапка сообщения чата строка текста, где ей не хватает места, время уходит на следующую строку целиком. Имя не режется нигде.
3. Вкладки (`shared/ui/Tabs`) и полоса разделов форума переносятся как текст: вкладка и черта после нее неразрывны, поэтому черта закрывает строку и никогда ее не открывает. Открытая вкладка первой, строка вкладок может кончаться чертой.
4. Ряд кнопок (`shared/ui/ButtonRow`) стоит одной строкой, каждая кнопка своей ширины. Кнопки, которым в строке не хватило места, уходят на следующую строку, как слова текста, и за колонку ряд не выходит. Кнопка, которая одна шире ряда, переносит слова подписи внутри себя и шире ряда не становится. Подпись кнопки полная ("Отключить двухфакторную аутентификацию"), ради ширины ее не сокращают. Ряд ничего не меряет: перенос делает раскладка.
5. Строка фильтров стоит одной строкой (раздел "Dropdown/Filter Standards"). Строка поиска чата держит поле не уже 160 и ставит кнопку под поле, где рядом им тесно (раздел "Ленты сообщений"). Полоса сохранения профиля говорит "Режим редактирования" и "Несохраненные изменения" и стоит одной строкой, а где колонке тесно, кнопки переносятся под слова.
6. Решает ширина, которую ряду дала его колонка, а не ширина окна.
7. Панель тегов редактора стоит всеми тегами на любой ширине и переносится между группами тегов: черта стоит в конце строки своей группы, переключатель [bbcode] / wysiwyg справа по середине строк. Где самая широкая группа и переключатель рядом не помещаются, переключатель уходит своей строкой под теги к правому краю редактора. Первая кнопка панели и правый край переключателя стоят по краям поля на любой ширине. Строка "0 слов | 0 / N символов" под полем стоит слева, первой буквой по краю поля, на любой ширине. Подсказка пустого поля стоит целиком в любое число строк, и поле растет под нее.
8. Строка подписки "- Название" вешает дефис: перенесенная часть встает под название, а не под дефис. Перечень имен под галочкой "Перенести мой черный список" называет всех, без "и еще N", а длинный список дочитывается страницами.

Держат гейт `styleSystem.spec.ts`, раздел "no text cut": в исходниках клиента нет `text-overflow: ellipsis`, `line-clamp` и обрезки из кода, кроме записей реестра с причиной и задачей, которая их снимет. E2e `common/one-line.spec.ts`: нет меню "Еще", нет кнопки, вкладки или ссылки со словом "Еще", "ЕЩЕ" или "…", нет части, спрятанной `[hidden]`, нет текста под многоточием или срезанного краем своей рамки, нет черты на разрыве подписи и строки вкладок, ряд кнопок не выходит за свою колонку. E2e `common/mobile-full-*.spec.ts` проверяют подписи, комментарии, пост, профиль, фильтры, чат и лог с длинными логинами на телефонах.

Остаются как есть:

| Что | Как на узкой ширине |
|-----|---------------------|
| Меню фильтров и меню сортировки | Не шире окна без полей страницы и в его пределах: висят от правого края кнопки и сдвигаются внутрь окна, если край кнопки их выносит (`useKeepInWindow`) |
| Номера страниц | Номеров столько, сколько помещается в строку, многоточия и переходы остаются (раздел "Pagination Standards") |
| Текст: абзацы, заголовки, названия в карточках | Переносится между словами, как в ячейках таблиц: прокрутка спрятала бы конец заголовка |
| Облака тегов и сетки карточек | Раскладываются по ширине, в этом их смысл |

## Отметить все прочитанным

Страница, которая отмечает прочитанным все разом (уведомления, форум), говорит это одной строкой под заголовком: "Непрочитанных: 4 | Отметить прочитанными" (`shared/ui/UnreadLine`). Строка мелкая серая, число жирное зеленое, как счетчики шапки, действие обычной ссылкой сайта; ссылку палец находит в полосе 32 в высоту, сама строка от этого не растет. Строка стоит, только пока непрочитанное есть: ни кнопки у заголовка, ни заштрихованной кнопки, когда отмечать нечего. От тысячи число пишется "999+". Это подпись из двух частей, слова с числом и ссылки, и переносится она между ними; слово "Непрочитанных:" стоит на любой ширине. Отказ сервера красной строкой под ней, строка остается для повтора. После отметки строка уходит вместе с числом, читалка слышит "Все уведомления прочитаны" ("Все топики прочитаны" на форуме), фокус встает на заголовок страницы.

Уведомления стоят таблицей сайта (`DataTable`) "Событие | Где | Кто | Когда", одно уведомление на строку, как личная почта DM2. "Событие" это заголовок сервера ссылкой туда, куда ведет уведомление, под ним серой подписью остальные сведения ("Персонаж: ...", "Причина: ... | Баллы: 1"); "Где" место ссылкой туда же и под ним серым место крупнее ("Комната: ...", "Блог: ..."); "Кто" люди ссылками на профиль; "Когда" дата и время в две строки. Слова события серверные, клиент только раскладывает присланные сведения по столбцам (`notificationParts`, `entities/notification/lib/parts.ts`). Запись, которую читают по одной, числа не носит. Непрочитанная отмечается жирным заголовком цветом ссылки и скрытым текстом ", не прочитано" внутри него для читалки, без заливки, значка и слов на экране; прочитанная серым `$text-muted`. Открытие записи (нажатие на ее заголовок или место) отмечает ее прочитанной: жирность уходит сразу, а счетчик шапки перечитывается после ответа сервера. Прочитанное остается в списке: крестика и "Перейти" у записи нет, и "Отметить прочитанными" строк не убирает, только снимает жирность.

Число непрочитанного у строки списка пишется после ее названия, как в шапке: "SolohinLex (2)", скобки серые, число жирное зеленое. Пилюли-счетчика и подкрашенной строки нет: прочитанная и непрочитанная строки различаются только числом.

## Ленты сообщений

Общий чат собран из частей ленты (`widgets/chat-feed`): рамка в пунктир, строка в ее верху (`ChatStrip`), лента с разделителями дат, панель действий над сообщением внутри рамки, кнопка "к последним", скелетон, красный блок с "Повторить", пустая лента и редактор под рамкой (`ChatComposer`). Над рамкой одна строка (`ChatSearchRow`): поиск по ленте ("Поиск по чату") и "Перейти к дате". Строки нет над лентой, про которую сервер ответил "пусто"; пока лента грузится и при отказе она стоит. "Перейти к дате" стоит словами на любой ширине. Поле поиска рядом с кнопкой не уже 160: рамка, лупа и место для запроса, а не только для своих слов "Поиск по чату". Где рядом с кнопкой ему остается меньше (средняя колонка чуть шире 1000), кнопка встает под поле, к его началу. Календарь "Перейти к дате" висит под строкой поиска у ее правого края, а не от кнопки, и поэтому не выходит за строку, когда кнопка стоит под полем. Календарь предлагает дни до сегодня. Какую часть истории показывает лента, решает одна логика (`useChatHistoryWindow`): день в адресе (`?date`), страницы от дня к последним сообщениям и выход из архива у низа последней страницы, строка-пояснение под строкой рамки, когда сообщения по ссылке нет (тогда стоят последние сообщения). Выбранный день остается в адресе и залит в календаре при следующем открытии, как до 5 октября: лента встает на первое сообщение дня, а у дня без своих сообщений на начало окна, которое сервер находит рядом, и оно может начинаться раньше дня. Длинное сообщение сворачивается после 500. Сообщение, к которому перешли, отмечается той же желтой вспышкой 2 секунды, что непрочитанное на всем сайте. Аватар 72 и колонка времени продолжения 72 на любой ширине. Шапка сообщения строка текста: где ей не хватает места, время уходит на следующую строку целиком, имя не режется, "(скрыть)" над открытым удаленным сообщением стоит частью строки. Поля нет у того, кому писать нельзя (гость, не участник закрытого эвента), и строки об этом над полем нет. Над сообщением нет transform и containment: фиксированные меню внутри (теги редактора правки) иначе открываются внутри ленты. Гейт `chatParity.spec.ts`: общий чат не держит своей копии ни одной части ленты. Поле поиска, "ближайший" строки эвентов, календарь и место даты в списке переписок держит e2e `common/mobile-full-chat.spec.ts`.

Переписка (`pages/messenger`) устроена как десктопный Telegram в цветах и контролах сайта. Середину рисует лента общего чата (`widgets/chat-feed`): рамка в пунктир, разделители дат, панель действий над сообщением, свертка длинного сообщения после 500, под рамкой тот же редактор разметки, что в общем чате; страница листается целиком, как общий чат. В верху рамки, на месте строки эвентов и ее видом (`ChatStrip`), строка переписки (`ConversationLine`): у переписки вдвоем имя собеседника ссылкой на профиль и "[online]" зеленым или "[offline]" серым, у группы название и "участников: N", дальше "поиск" и "…" серыми кнопками-ссылками. "поиск" (и Ctrl+F) открывает под строкой строку поиска чата: поиск по переписке и "Перейти к дате". "…" открывает меню панелью сайта: "Перейти в профиль" у переписки вдвоем, "Очистить историю" (только для себя) и "Покинуть группу" у группы, каждый пункт только по признаку сервера (`viewer.canClearHistory`, `viewer.canLeave`). Очистка и выход спрашивают окном, после выхода страница возвращается к списку. Поле стоит только по ответу сервера (`chat.viewer.canWrite`) и не стоит, пока переписка в пути. "Переписка не найдена" пишется только по 404, под ней ссылка "Все переписки". Значок якоря у сообщения обычная ссылка на него (`?msg=`): лента встает на сообщение и подсвечивает его.

Список переписок стоит справа, на месте правой колонки сайта, которой у переписки нет, и на 1000 и уже тоже остается рядом с перепиской. Сверху поиск собеседника, под ним строки: квадратная картинка, имя, время и выдержка последнего сообщения, число непрочитанного "(N)" сразу после имени. Без открытой переписки на месте ленты пустая рамка с серой строкой "Выберите переписку справа или найдите собеседника через поиск". Край между перепиской и списком тянут мышью, пальцем или стрелками: список сужается до 200, а уже переходит в узкое состояние, как папки Telegram, только картинки и "(N)" под ними; лупа сверху возвращает слова и ставит курсор в поле. Ширина списка запоминается в браузере читателя (`useListWidth`), страница списка (`?number`) сохраняется во всех переходах внутри переписки. Держат `ChatView.spec.ts`, `MessengerPage.spec.ts`, `ChatsList.spec.ts`, `useListWidth.spec.ts` и `listPage.spec.ts`.

Строка эвентов общего чата говорит все слова на любой ширине: где рамка уже строки, строка переносится как текст и полоса растет (`ChatStrip` без `nowrap`), вбок она не листается и ничего не прячет. Название эвента это текст, целиком; описание открывает "описание" рядом с ним, список ближайших открывает "+2 запланировано". Строка списка ближайших эвентов тоже переносится как текст, название, дата и "закрытый" целиком. В "ближайший 15.10" слово и день неразрывны (U+00A0, как после "в" в дате и времени): день не остается один на строке, а копируется обычным пробелом. Что эвентов нет, строка говорит только по ответу сервера ("Нет запланированных эвентов"). Пока список в пути, на месте эвента серая полоса, а отказ сервера дает "Эвенты не загрузились | повторить".

## Состояние записи

Состояние записи пишется словом, без подложки, рамки, скругления и значка рядом: "Заявка отклонена", "Включена". Цвет по смыслу: зеленым то, что действует ("включена", "одобрена"), красным отклоненное и то, что не удалось прочитать ("Заявка отклонена"), остальное цветом текста или серым ("на рассмотрении", "истекла"). Других цветов у состояния нет, а у слова состояния обращения и записи бана цвета нет вовсе. Красная "*" после состояния обращения не цвет состояния, а метка того, от кого ждут ответа (раздел "Обращение"). Запись бана описана ниже в этом разделе. Если состояние у всех строк списка одно, слова нет вовсе: в очереди запросов на смену имени только ожидающие. Если состояние выделяет одну запись среди прочих, запись стоит отдельно под серой подписью группы, а не красится и не обводится: "Текущая сессия" и "Другие сессии" в сессиях аккаунта. Канал уведомлений в аккаунте стоит строкой в рамке, как сессия над ним: название, под ним серой строкой состояние "Подключен" или "Не подключен" без цвета, справа одна кнопка ("Подключить", "Отмена" или "Отключить"); у подключенного под строкой галочка "Включить уведомления" и столбец галочек под подписью "Что присылать", во время привязки шаги со ссылкой на бота и командой обычными словами, без поля и кнопки копирования. Значение в строке сведений ("Включена: 01.09.2026 в 09:37") не рвется: где ему не хватает места рядом с подписью, оно встает под нее целиком. Персонаж в составе игры "В игре" пишется цветом текста и одной строкой, выбывший серым (владелец, 12 октября 2026: зеленый только хорошее).

Записи лога предупреждений (`WarningCard`, открытый `/warnings` и модераторский список) зеленого не носят: ничего позитивного в них нет. Запись красная, пока у нее есть баллы, и серая без них (владелец, 12 октября 2026: "Давай серое при изменении на 0 или устном. Если баллы есть, то красное"). Устное предупреждение серое. Предупреждение, баллы которого потом изменили до 0, серое вместе со строкой изменения. Изменение красится по баллам, которые оно оставило. Предупреждение подписано баллами, с которыми выдано ("Предупреждение (3 балла)"), изменение баллами после него ("Изменение баллов (1 балл)"), обе подписи через одно склонение `pointsLabel`. Под записью показан текст, к которому выдано предупреждение, снимком на момент выдачи; о позднейшей правке этого текста запись ничего не говорит, и сервер момент правки не отдает. Запись за профиль показывает так же снимок профиля, столбцом над подписью на любой ширине: собранный из тех же частей и в тех же размерах, что страница профиля: аватар 220 без скругления (не шире записи, высота по пропорции, рамка и фон как в профиле), строка "Статус: ..." видом строки статуса профиля, "О себе" заголовком вида вкладки профиля и под ним текст разметкой, свернутый после 300; чего у профиля не было, того в снимке нет. Своих размеров у снимка нет: `WarningCard.spec.ts` сверяет его шрифты со стилями профиля. Подпись у нее "Профиль пользователя, Автор: имя", у записи без объекта "Пользователь: имя". Причина предупреждения стоит разметкой. В модераторском логе у записи с картинкой в конце подписи "Удалить картинку" с вопросом окном `ConfirmDialog`, у записи о самом модераторе этого действия нет, а сервер такой просьбе отвечает 403 и ничего не помечает. Держат `WarningCard.spec.ts`, `warningLabels.spec.ts` и `ModerationWarnings.spec.ts`.

Запись бана (`BanLogCard`, "Последние баны") пишется фразой бота DM2: модератор жирной ссылкой на профиль, "выдал(а)" или "снял(а)" без подчеркивания, вид бана, "пользователю" или "с пользователя", логин жирной ссылкой, у небессрочного "до" и дата жирным через неразрывный пробел, точка, пустая строка, "Примечание от модератора:" и строкой ниже само примечание цитатой `[quote]` сайта. Заголовок примечания стоит всегда, как на DM2, а цитата только при непустом примечании. Бессрочный бан назван словом, без "до". Выдача и снятие идут отдельными записями. Текст стоит по ширине с переносами по настройке "Перенос слов", как текст комментария. Красного и зеленого в записи нет, цветные только ссылки. Под записью подпись "Выдан: дата" или "Снят: дата", у записи выдачи в ней "Снять бан" по признаку сервера `canLift`. В правом нижнем углу номер записи (`number`, сквозной по журналу, самая старая 1) серой ссылкой без подчеркивания, как номер комментария: он ведет на `?entry=N#ban-N`, страница открывается на странице журнала с этой записью, ставит в адрес номер найденной страницы, встает на запись по центру окна и подсвечивает ее. Держат `BanLogCard.spec.ts`, `ModerationBans.spec.ts` и e2e `common/ban-log.spec.ts`.

## Обращение

Обращение работает и выглядит как топик с ответами. Блок везде один, `widgets/ticket-thread` (TicketThread): рамка записи модерации (`RecordBlock`) с причиной в заголовке, жирным и с пунктиром под ним, под ним текст и подпись топика: "Автор: имя [буква роли] [online], дата | Ответы (N) | состояние". Текст это только то, что написал пользователь, разметкой. Что форма спросила кроме текста (нарушитель, ссылка на нарушение, контакт, у гостя его почта), сервер при приеме вписывает в текст обычными строками (`TicketService`), поэтому своих строк сведений, серого и мелкого в блоке нет, и клиент к тексту ничего не добавляет. Текст стоит по ширине с переносами по настройке "Перенос слов", как текст комментария. Число в "Ответы (N)" ссылка на страницу обращения, как число комментариев у топика. В "Моих обращениях" автора в подписи нет, удаленный автор подписан "Аккаунт удален", гость "Гость". Состояние стоит словом подписи: "Ожидает ответа модерации", "Ожидает ответа пользователя", "Закрыто", "Спам" (`entities/ticket/lib/labels.ts`). Своих цветов у блока нет, кроме буквы роли, [online] и одной метки: красной "*" через пробел после состояния у того, от кого ждут ответа (`awaitsReader`), той же звезды, что у комнаты в меню игры (`GameRoomLink`). Ее видит вошедший автор при "Ожидает ответа пользователя" и модератор, которому обращение видно, при "Ожидает ответа модерации", кроме модератора, подавшего его сам; у гостя ее нет. Метка стоит в "Моих обращениях", в очереди "Обращения" и на странице обращения. В списке причина ведет на страницу обращения, длинный текст сворачивается после 150; на странице обращения текст целиком.

Под блоком переписка (`TicketConversation`): ответы тем же `CommentItem`, что у топика, всегда в компактном виде, какой бы вид комментариев ни выбрал читатель, от старого к новому с номерами, без "Редактировать", "Удалить", "Предупреждение" и сердца у любого читателя. Ответ гостя подписан "Гость" без ссылки. Под перепиской форма ответа (`TicketAnswerForm`): редактор "Написать ответ..." со счетчиком до 10000, а не до 50000, как у комментария топика (число держит клиентская копия `TICKET_TEXT_MAX_LENGTH`, а `BodyTextLimitShould` сверяет ее с серверной), и "Отправить" под ним слева. Форма стоит только по признаку сервера `canComment`. У закрытого обращения формы нет, на ее месте плашка `RefusalNote` "Обращение закрыто <дата в время>, закрыл(а) <имя>."; у открытого, где писать уже нельзя, плашка "В обращении 100 ответов, для продолжения подайте новое обращение". Пустая переписка автора говорит, что ответ появится здесь и придет уведомление.

Назначения нет: никто не берет обращение в работу, отвечает и закрывает любой модератор, которому сервер его показывает. Предупреждения и бана в обращении нет. У модератора (признак `canResolve`) над редактором формы ответа стоит список "Статус" обычным select форм сайта, как в окнах предупреждения и бана: "Ожидает ответа пользователя" (выбран сразу), "Закрыто", "Спам". Статус уходит вместе с ответом одним запросом. При "Закрыто" и "Спам" текст не обязателен: пустое поле отправляет только смену статуса. Автор и гость статуса не выбирают, их ответ ставит "Ожидает ответа модерации". Блок, переписка и форма одни у автора, гостя и модератора и различаются только тем, что присылает сервер. Слов назначения в клиенте нет, это держит `ticketBody.spec.ts`.

Гость приходит к своему обращению по ссылке с токеном. Над блоком на его странице одна фраза со ссылкой на эту же страницу, текст ссылки полный адрес: "Ответ появится на этой странице: <адрес>. Сохраните ссылку, чтобы вернуться к обращению." Теми же словами говорит карточка после отправки формы, только "на странице обращения". Кнопки копирования и строки с номером нет. Фразы держит `copy-rules.spec.ts` (`REQUIRED_COPY`).

## Выделение и копирование текста

Текст интерфейса выделяется и копируется целиком. `user-select: none` разрешен ровно в двух местах: у горизонтального `DashSeparator`, где "- - - -" это линия, а не слова, и у метки "RU" адресного блока сайдбара (`SiteAddresses`), где буквы работают иконкой и не должны участвовать в выделении. Декоративный префикс "- " в строках сайдбара несет `aria-hidden`, но выделяется и копируется вместе со строкой: правильная вставка "- Игры", а не "Игры". Однострочная композиция обязана копироваться одной строкой, без склеек и лишних пробелов: подпись ссылки пишется вплотную к тегу, иначе компилятор шаблона добавляет к ней ведущий пробел.

## Цвет ссылок игр и блогов по статусу

Ссылки-названия игр и блогов раскрашиваются по статусу единообразно везде (сайдбары, таблицы /games и /blogs, профильные таблицы, хлебные крошки постов, страница подписок): **зеленый** ($accent-green) — "новый" модуль (активирован менее 7 дней назад и не закрыт); **приглушенный серый** ($text-muted, до hover) — Closed; остальное (оформляющиеся, активные старше 7 дней) — обычный $link. Серый приоритетнее зеленого. Архивные комнаты трактуются как закрытые — тем же приглушенным серым; архивность передается цветом (и, где уместно, тегом "архив"), НИКОГДА суффиксом в самом названии. Текстовые бейджи статуса (GameStatusBadge/BlogStatusBadge) цвета не несут.

## Переход к посту выглядит ссылкой везде

Все элементы "перейти к посту" - глиф "↩" в подвале поста вне его страницы и номер в подвале на его собственной странице - красятся $link / hover $link-hover, единообразно во всех контекстах. Один и тот же элемент не носит два наряда.

Тултип у всех называет действие ("Перейти к посту"). Решение владельца 2026-08-25; заменяет более раннее правило "действие против идентификатора", стоявшее на неверной посылке о контекстах номера.

Номер оценки "#N" тоже в этой группе: он стоит в строке оценки после даты ("+1 от X, дата, #1 | Редактировать | Удалить") и красится $link. Решение владельца 2026-10-05 ("У оценок постов что ты сделал с #1? Почему он справа?"), отменяет вид 2026-09-24 в правом углу строки.

## Animation Standards

| Тип | Duration | Easing |
|-----|----------|--------|
| Fast (hover) | 0.1s | ease |
| Normal | 0.15s | ease |
| Slow (modals) | 0.3s | ease |

`prefers-reduced-motion` покрывается глобальным правилом в `Reset.sass` (0.01ms duration для всех transitions и animations). Не нужно добавлять media query в каждый компонент.

Все раскрытия/сворачивания контента (спойлеры, NSFW, "показать полностью", аккордеоны, раскрываемые списки) анимируются единообразно плавно — единые токены длительности и кривой из `_Animations.sass`; мгновенные тогглы высоты запрещены.

Любой разворачиваемый КОНТЕНТ обязан работать с глобальной кнопкой "Развернуть/Свернуть все" (реестр expandables); ручной тоггл участника обязан вызывать `notifyExpandableChanged`. Секции с подменяемым контентом строятся ТОЛЬКО на `useExpandableSection` — он дает весь контракт разом (плавность единым темпом, реестр, семантика ручного тоггла, глобальный класс зоны `.expand-zone`); собирать это поведение вручную по частям запрещено. Для v-for-аккордеонов и раскрытий с постоянно смонтированным контентом — CSS-only глобальный `.expand-fold` (grid-rows, тот же темп). Текстовая обрезка — `TruncatedContent` (line-snap ниже).

Границы реестра: ИНСТРУМЕНТАЛЬНЫЕ раскрытия (инлайн-формы создания/редактирования, аккордеоны настроек) анимируются так же (`useAnimatedHeightToggle`/`.expand-fold`), но в реестр НЕ входят — "Развернуть все" читает контент, а не открывает инструменты. Персистентные сайдбар-секции (localStorage) тоже вне реестра, но анимируются едиными токенами. Показ УДАЛЕННОГО контента (модераторские "Показать/Скрыть" у удаленных комментариев/сообщений) — вообще не сворачивание/разворачивание: это осознанное модераторское действие, простой мгновенный свап вне контракта; "Развернуть все" никогда не вскрывает удаленное.

**Файл:** `src/DM.Web.Client/src/assets/styles/_Animations.sass`

## Текст поста и комментария

Текст поста (игровой и коричневый), комментария в обоих видах, топика и публикации и текст записи модерации (`RecordBlock`: лог предупреждений, обращение, бан) стоят как текст DM2 на любой ширине, телефон тоже: 16 на шаге строки 20, по ширине, с переносами слов, пока включена настройка "Перенос слов" (класс `hyphenated` от `useUiStore().hyphenateWords`); без нее переносов нет. Правило одно, миксин `+body-text` в `_BbcodeContent.sass`. Пустая строка автора дает между абзацами 40 от верха до верха. Коричневый текст стоит на 33 под игровым, заметно дальше пустой строки; под бросками кубиков он стоит на их 22. Шаг задает сам блок текста, а не колонка поста: окно правки и полосы вокруг текста остаются на шаге страницы. Чат и переписка держат свой шаг.

Пост повторяет размеры DM2, снятые замером на 1366. Колонка автора 140 (содержимое 128, портрет во всю ширину колонки), текст в 22 от верха карточки и в 10 от колонки и от правого края. Броски стоят плоской полосой фона `$bg-element-accent` без рамки и скругления, от левого края текста до края карточки, по 22 до соседних блоков, строки бросков по ширине, как у DM2; все броски поста видны, без свертки. Под последним блоком "Отредактировано" 12, номер поста ссылкой в правом нижнем углу карточки. Посты комнаты идут через 20. Полный вид комментария устроен как пост: карточка с полем 5, слева колонка 140 с именем, буквой роли и [offline], аватаром 128 в рамке портрета, датой и сердцем лайка, справа текст с теми же отступами, под ним строка 12 "Отредактировано ... | Редактировать | Удалить | Предупреждение", номер в правом нижнем углу. Компактный вид колонки не имеет. Скелетоны поста и комментария повторяют эти размеры (`GamePostSkeleton`, `CommentSkeleton`).

## Комната игры

Комната постов читается во всю середину страницы, как на DM2: у нее левая колонка и нет правой (своя запись маршрута без вида `right`, раздел "Телефон и выдвижная панель"). Форма поста стоит без рамки, плашки и заголовка над ней, как форма комментария, полями в порядке DM2 с подписями DM2: "От лица:" (у ведущего, когда выбор больше одного), "Текст сообщения:", "Броски кубиков" со ссылкой "Очистить", "Комментарий:", "Вложение", "Я жду хода от:" (у мастера, последним полем) и "Отправить". Плейсхолдеров в полях нет.

Броски набираются строкой DM2 (`DiceComposer`): над ней галочки "Показывать всем результаты бросков" и "Броски взрываются максимум [ ] раз", сама строка "[число] x D3 D4 D6 D8 D10 D12 D20 D [грани] D100 + [модификатор]", за ней "Комментарий" и поле на остаток ширины, под строкой набранные броски, у каждого крестик. Кубики это кнопки сайта, кубик с любыми гранями бросается кнопкой "D" или Enter в поле граней. В опубликованном посте броски стоят полосой (раздел "Текст поста и комментария").

В меню игры замок стоит только у закрытой комнаты: зеленый, если зритель может ее открыть, светло-серый, если нет. Комната, которую зрителю открыть нельзя, стоит в меню не ссылкой, цветом текста и без "(0)", а по прямому адресу комната постов и чат-комната отвечают страницей "не найдено" сайта, адрес остается. Чьи персонажи пишут в чужой закрытой комнате, строка меню не раскрывает.

Настройки комнат стоят как на DM2: сверху форма "Создать новую комнату" ("Название:", "Тип:", "Доступ:", закрытая по умолчанию, и "Создать"), под ней "Настройки комнат" одной таблицей всех комнат: "#", "Название", "Тип", "Доступ", "Активность" и "Удалить" через окно, а под ячейками каждой комнаты строки "Игроки:" (отмеченные пишут), "Читатели:" с полем добавления и настройки самой комнаты. До "Сохранить" ничего не уходит, кнопка отвечает "Сохранено" и шлет каждой комнате только то, что в ней изменилось.

## Формы игры и блога

Создание и настройки игры и блога стоят одной формой рядами, как формы DM2 (`_FormRows.sass`, `+form-row`): подпись с двоеточием в колонке 160 слева, поле справа, подпись длиннее колонки переносится. Подпись видом подписи поля страницы (14 жирным). Поле, которому нужна вся ширина (редактор разметки, теги, схема атрибутов), стоит во всю ширину, а подпись над ним, как "Описание" и "Теги:" на DM2. Блоков с заголовками внутри формы нет, у раздела настроек один заголовок "Общие настройки". Серых подсказок, которых нет на DM2, под полями нет; подсказка стоит, только где она говорит, что делает поле ("Не менее 200 символов" у описания, "Используйте эту ссылку, чтобы позвать в игру" под ссылкой на игру).

Игра, которую еще не начали, называется оформляющейся ("Оформляется"), блог оформляющимся, на экране и в документах; слова "черновик" о модуле нет. Создание игры спрашивает состояние ("Оформляется", по умолчанию, или "Оформлен"), начинает оформляющуюся игру пункт "Начать игру" в меню игры. Обсуждение игры выбирается словами DM2: "Доступно всем без ограничений" или "Доступно посторонним только для чтения"; выключателя комментариев нет ни у игры, ни у блога, ни у публикации (раздел "Недоступное не показывается"). Блог спрашивает "Кто видит оформляющийся блог:". Ссылка на игру в настройках обычная ссылка с полным адресом, кнопки копирования нет.

Теги выбираются пузырями фильтра, выбранный тег нажат (строка "Выбор" раздела "Button/Control States").

## Обрезка текста (line-snap)

Любая обрезка текста по высоте ("показать полностью" и подобные) режется строго МЕЖДУ строками: кламп снапится к низу последней строки, целиком влезающей в бюджет, по ФАКТИЧЕСКИМ line-box'ам контента (замер в рантайме), а не фиксированными px и не предположением о равномерной сетке. Единая line-height у многоблочного контента не гарантируется — межабзацные отступы и разные line-height сдвигают строки с любой предполагаемой сетки, поэтому мерить нужно реальные строки. Полусрезанная последняя строка — дефект.

Бюджет свернутого блока один на любой ширине: телефон рисует колонку 1366 и показывает свернутым столько же текста (отзыв на главной: три строки, новость: 150). Скелетон новости резервирует ту же высоту. Держат `SpeechBubble.spec.ts` и `RecentNews.spec.ts`.

## Картинки в тексте

Картинка в тексте поста, комментария и сообщения рисуется не выше 500 px, как
на DM2, при любой высоте окна (`--bb-image-max-height` в `_BbcodeContent.sass`),

## Переключение темы

Переключение темы — **мгновенное**. CSS custom properties snap между значениями light/dark.

**Механизм** (`App.vue`): на время смены класса `theme_Light`/`theme_Dark` на `<html>` добавляется класс `.no-transitions`, блокирующий все CSS transitions через `!important`. Forced reflow (`offsetHeight`) гарантирует, что все значения обновятся за один кадр. После reflow transitions разблокируются.

**CSS** (`ThemeVariables.css`):
```css
html.no-transitions,
html.no-transitions *,
html.no-transitions *::before,
html.no-transitions *::after {
  transition: none !important;
}
```

**JS** (`App.vue`):
```ts
html.classList.add("no-transitions");
// ... swap theme classes ...
void html.offsetHeight; // Force reflow
html.classList.remove("no-transitions");
```

**Правила:**
1. **`transition: all` запрещен.** Всегда перечислять свойства явно (performance, predictability).
2. Per-component hover/focus/active transitions на цветовые свойства **допустимы** — `.no-transitions` автоматически подавляет их при смене темы.
3. Для стандартных transition — `+transition-safe()` / `+transition-safe-multi()` из `_Animations.sass`.
4. Любой новый компонент с `transition:` автоматически покрывается `.no-transitions` — никакого opt-in не нужно.

## Avatars

Используйте компонент `<AvatarImg>` (из `@/shared/ui/AvatarImg`) — он сам решает,
какой URL грузить из `picture` объекта и формирует srcset для DPR-aware
загрузки на retina.

```vue
<AvatarImg :picture="user.picture" :alt="user.username" :size="48" />
<AvatarImg :picture="user.picture" :alt="user.username" :size="220" prefer-original eager />
```

Сервер отдает 3 URL в `picture: { smallUrl, mediumUrl, originalUrl }`:
- `smallUrl` — 100×100 (через imgproxy, AVIF/WebP auto)
- `mediumUrl` — 400×400 (через imgproxy)
- `originalUrl`: ≤1024 px aspect-preserving (прямой адрес S3)

Подробнее: [UPLOADS.md](../architecture/UPLOADS.md).

## Состояния данных

Каждое представление данных обязано иметь **четыре состояния**: загрузка (skeleton) → ошибка → пусто → контент.

| Правило | Пояснение |
|---------|-----------|
| Ошибка ≠ пусто | При ошибке запроса показывается сообщение об ошибке, а не empty state |
| Нет вечных skeleton | Skeleton живет только пока идет загрузка; при ошибке сменяется сообщением |
| Тексты ошибок на русском | "Не удалось загрузить..."; сырые `error.title` с сервера пользователю не показываем |
| API-клиент не бросает исключения | Возвращает `{ data, error }` — поле `error` проверяется всегда |
| Stale-while-revalidate | При перезагрузке уже показанные данные не прячутся под skeleton |

## Всплывающие сообщения

Плашка ставится только там, где она необходима и где на самой странице, у
места действия, написать нельзя (правило владельца от 26.09.2026). Это одинаково
для подтверждений и для отказов: результат нажатия пишется у кнопки, у строки,
у формы, где читатель нажимал и куда он смотрит, а не в углу экрана. Отсюда
правило, которое дороже всех остальных в этом разделе: **прежде чем писать
плашку, найди на странице место, где стоит нажатие.** Если место есть, плашки
быть не должно.

Разбор каждого действия идет по трем полкам.

| Полка | Что видно после действия | Что делать |
|-------|--------------------------|------------|
| Результат виден сам | Строка ушла из списка под курсором, значение сменилось, страница уехала на созданное, окно закрылось и за ним новое состояние | Подтверждения нет |
| Результата не видно, а место есть | Экран после нажатия ровно тот же: форма настроек с теми же значениями, анкета, профиль, строка, которую сервер не принял | Ответ у места нажатия: кнопка "Сохранено" (ниже) об успехе, строка у места об отказе |
| Места на странице нет | Нажатие в меню, которое закрылось до ответа, кнопка сайдбара, нажатие в самой плашке, в фоне; окно, после которого на странице не меняется ничего; ушло письмо человеку; истекла сессия | Плашка. Это ее настоящая работа |

**Отказ пишется у места нажатия.** Строка отказа стоит под кнопкой, которую
нажали, под строкой списка, в которой нажали, над подвалом формы, в карточке
окошка подписки. Форма и строка остаются на месте, с тем, что было набрано, и
строка держится до следующего нажатия того же места. Это общий компонент
`ActionResult` (`shared/ui/ActionResult`). Место с одной строкой берет для нее
`useActionResult` (`shared/lib/composables`), место, которое держит строку
само, например по строке на каждую запись списка, берет `refusalHere`
(`shared/lib/errors`). Вид один на весь сайт: красный текст
размера второстепенного текста, без фона, рамки, скругления и значка, от
левого края места, на шаг `$small` ниже. Место, которое само разводит строки
зазором колонки, снимает этот шаг через `--action-result-margin`, а не своим
`margin`. Слова строки - слова `describeFailure`: фраза сервера, если он ее
дал, поле по подписи на экране, если сервер отказал по полю, и фраза места,
если сервер не сказал ничего. Ожидание 429 строка говорит с секундами, а
`useActionResult` держит кнопку запертой, пока они не выйдут.

Окно пишет отказ в себе тем же порядком, это правило раздела "Dialog
Standards".

**Кнопки сайдбаров отвечают плашкой.** Это решение владельца: пункты меню игры
и блога в левой колонке (подписка, смена статуса без вопроса) и голос в опросе
правой колонки говорят об отказе плашкой, а не строкой под пунктом. Удача видна
на самом пункте: подпись сменилась, статус сменился, голос учтен. Вопрос перед
действием из меню задается окном, как везде, и отказ на него пишется в окне.

**У отказа один носитель.** Перехватчик ответов держит каждую плашку отказа,
которую он поднимает (403 с фразой сервера и без нее, 429, 5xx), до конца
текущей задачи. Место, которое пишет отказ у себя, снимает ее
(`takeOverRefusal`; это делают `useActionResult` и `refusalHere`), и отказ
сказан один раз, у места. Запрос, отказ которого никто на странице не показал
(фоновая загрузка, отметка прочитанного), остается с плашкой. Два отказа
остаются с плашкой всегда: истекшая сессия (401) и запрос, который не дошел до
сервера (статус 0). Они не про нажатие, а про читателя и его сеть, и строка у
места о них молчит. Флаги `ownsRefusal` и `ownsRateLimit` на запросе по-прежнему
работают для окон и гостевых форм: перехватчик о таком запросе молчит сразу.
Флаг ставит вызывающий, а не метод api: у одного метода бывают вызовы с ответом
на экране и без.

**Плашка общего отказа начинается с фразы вызова.** Если сервер назвал только
общее, "недостаточно прав" (заголовок проверки прав или 403 без тела) или ошибку
сервера (5xx), и место отказ не показало, перехватчик поднимает плашку "Запрос
не выполнен: ошибка сервера", а вызов `notifyFailure` отдает ему свою фразу:
"Не удалось выйти из аккаунта: ошибка сервера". Отказ со своей фразой сервера
идет как есть. Фраза вызова обязана влезать в плашку и с хвостом, и
`toastWidth.spec.ts` меряет ее в обоих видах.

Загрузка страницы забирает отказ себе: строка или блок ошибки вместо
содержимого и есть ответ, а плашка в углу над пустой страницей не объясняет
ничего, и пустое состояние вместо ошибки - ложь. Загрузка через
`useGuardedRequest` снимает плашку перехватчика сама, потому что каждый ее
экран показывает `error` у себя. Загрузка из двух запросов снимает плашку
каждого по мере прихода (`shownOnPage`): плашка держится только до конца той
задачи, в которой пришел ответ, и первая встала бы раньше, чем придет второй.

**Подтверждение сохранения несет кнопка, а не плашка.** Форма настроек после
ответа сервера выглядит в точности как до него, и сказать об удаче может только
она сама: `useSavedState` сравнивает форму с сохраненной копией, кнопка читается
"Сохранено" и не нажимается, пока они совпадают, и возвращается к "Сохранить",
как только читатель что-то поменял. Без таймера: вспышка гаснет раньше, чем
читатель поднимет глаза от поля, и ничего не оставляет тому, кто посмотрит через
минуту.

**Копирование отвечает на контроле.** Буфер обмена экрану не виден, но
контрол, по которому нажали, - виден, и у него есть место на два слова.
`useCopyFeedback` держит одну идиому на все копирование сайта: контрол с
подписью на две секунды читается "Скопировано", при отказе "Не удалось", потом
возвращается к своему слову. Свои сроки и свои слова не заводятся. Идиома
держится на подписи: контрол без слов ответить не может. Копируют так только
то, что не адрес: секрет и резервные коды двухфакторной аутентификации. Кнопки
"Скопировать ссылку" на сайте нет: номер комментария и номер записи бана в
правом нижнем углу, значок якоря у сообщения чата и переписки, адрес обращения
гостя и ссылка на игру в настройках это обычные ссылки, без подсказки и без
плашки, и их адрес копируют как адрес любой ссылки.

**Плашка - это не уведомление.** Уведомления ([`NotificationCategory`](../../src/DM.Domain.Core/Enums/NotificationCategory.cs))
рассказывают о том, что сделал кто-то другой, пока тебя не было: они копятся
непрочитанными и уходят в Discord и Telegram. Результат собственного нажатия
уведомлением не бывает.

Форма самого сообщения:

| Правило | Пояснение |
|---------|-----------|
| Одна строка | Не длиннее 64 знаков в готовом виде - столько держит коробка в 620px. Гейт `toastWidth.spec.ts` |
| Одно предложение, без точки | Второе предложение в плашке - признак того, что действие надо разбирать по полкам выше, а не дописывать текст |
| Слова с экрана | Плашка называет вещь ровно так, как ее называет экран и [глоссарий](../references/GLOSSARY.md). Свой синоним - дефект |
| Понятно само по себе | Читатель мог увести взгляд с места нажатия. "Введите название" без указания чего - дефект |
| Нажатие стоит внутри фразы | Слова нажатия помечаются в тексте квадратными скобками: `попробуйте [RU-прокси]`. Подпись, приставленная в конец, либо повторяет сказанное, либо заставляет искать, к чему она |
| Значение в тексте | Подстановка объявляется в `WIDEST`/`WIDEST_KIND` того же гейта в самом широком виде, иначе длина не меряется |

**Каждая плашка записана поименно.** Гейт `toastRegistry.spec.ts` держит
список всех плашек сайта, подтверждений и отказов, с доводом, почему у этого
нажатия нет места на странице. Плашки перехватчика, слова которых строятся из
ответа, записаны там по вызову. Незаписанная плашка роняет сборку; запись,
которой больше нет в коде, роняет тоже, чтобы список не протух. Новая плашка -
это новая строка реестра и довод, который проверяет ревьюер.

Правило завелось после сплошного разбора 20 сентября 2026: подтверждений на
сайте стало в несколько раз меньше, и три ручных прохода подряд пропустили
полтора десятка, потому что текст брался по ключу из таблицы, а не писался
литералом. Реестр нашел их за один прогон.

Если на месте контрола уже встала строка состояния, вторую половину действия
несет она же ("Двухфакторная аутентификация отключена, сессии завершены"), а не
плашка рядом. Третья полка применяется только там, где места нет совсем.

## Недоступное не показывается

Чего зрителю нельзя, того на экране нет: ни кнопки, ни формы, ни пункта меню, ни строки отказа на их месте. Читать открыто всем и всегда: обсуждения игры, блога, публикации и топика читает всякий, кому видно место, гость тоже, и выключить комментарии нельзя нигде. Чтение закрывают закрытая комната игры, неопубликованная публикация, модуль, который зрителю не виден целиком (оформляющийся без открытого показа или на премодерации), и личное (переписка, уведомления, заметки). Черный список и бан запрещают только писать, и только в своих местах (правила сервера в [AUTHORIZATION.md](../architecture/AUTHORIZATION.md), раздел "Что открыто на чтение"). Заштрихованный контрол, который ничего не делает, тоже отказ, нарисованный заранее, и он тоже не рисуется. Сервер отказывает все равно, клиент только не предлагает того, чего сервер не примет.

| Случай | Как |
|---|---|
| Обсуждение, в котором зрителю нельзя писать: игра "Доступно посторонним только для чтения" для того, у кого в ней нет роли, закрытый топик, черный список игры или блога | Обсуждение читается целиком. Формы нет, на ее месте плашка `RefusalNote` (проп `closedHint` у DiscussionSection; у топика "Топик закрыт для комментариев"), гостю она же вместо "Войдите": "Писать в обсуждении могут только участники игры", "Вы в черном списке этой игры: писать в обсуждении нельзя", "Вы в черном списке этого блога: писать комментарии нельзя" |
| Такое обсуждение пусто | Раздел на месте: строка фильтров, "Комментариев пока нет" и подпись. Пункт "Обсуждение" в меню игры и блога есть всегда. У неопубликованной публикации раздела нет: читать там нечего |
| Раздел форума, где топики открывает только модерация ("Новости проекта", "Конкурсы"), и забаненный в любом разделе | Кнопки "Создать топик" нет. Гостю "Войдите, чтобы создать топик" только там, где вход открывает топик обычному участнику |
| Рецензия на игру: новичок, нет поста в игре, своя рецензия уже есть | Формы "Оставить рецензию" нет, только список |
| Оценка поста: свой пост, уже оцененный, оценка в той же игре за последние три дня | "+0" не раскрывается, под оценками формы нет. Оценка, отправленная со страницы, закрывает и остальные посты этой игры на ней |
| Форма поста в комнате: персонажу комната не дает "Может писать" (в открытой тоже: открытость про чтение, писать могут только те, кого добавили) | Персонажа нет в "От лица"; игроку без такого персонажа формы нет |
| Поле чат-комнаты игры: зрителю, который читает, но не мастер, не ассистент и не держит "Может писать" на себя или на своего персонажа в игре, гостю тоже | Сообщения читаются, поля и "Отправить" нет, на их месте плашка "Писать здесь могут мастер, ассистенты и те, кому мастер разрешил писать в этой комнате". Вход права писать не дает, поэтому гостю стоит та же плашка, а не "Войдите" |
| Комната игры, постов или чат, которую зрителю открыть нельзя (закрытая без доступа, скрытая, несуществующая), а зритель дошел до нее по адресу | Страница "не найдено" сайта, адрес остается, сообщения и посты не запрашиваются. В меню игры такая комната стоит не ссылкой (раздел "Комната игры") |
| Чат-комната игры у гостя | Открытую гость читает, как всякий, кому видна игра, и новые сообщения приходят ему тоже. Плашка "Войдите, чтобы читать чат игры" на месте рамки и поля стоит, только когда сервер на чтение ответил 401 (сессия истекла) или список, прочитанный до выхода, еще открывает закрытую комнату. Вход читает комнату заново, без перезагрузки страницы |
| Личное сообщение тому, кто внес зрителя в черный список с включенным "Блокировать личные сообщения" | В профиле нет "Написать сообщение", первой в ряду действий стоит подписка; в переписке вдвоем нет поля и "Отправить", на их месте ничего, переписка читается |
| Действие, которое сервер отклонит по тому, что уже видно на экране (удаление группы с тегами, оценка своего поста) | Контрола нет; почему, говорит сама строка (число тегов, автор) |
| Снятие бана, от которого сервер откажет: свой бан, бессрочный не администратору, истекший, уже снятый | У записи выдачи нет "Снять бан", решает признак сервера `canLift` у бана |
| Обращение, где писать нельзя (закрыто, в переписке сто ответов) или нельзя выбрать статус (автор, гость, модератор без права) | Формы нет, на ее месте плашка закрытия или плашка о ста ответах; списка "Статус" в форме нет без `canResolve` |
| "Удалить картинку" у записи лога о самом модераторе | Действия нет: пометка от владельца картинки не снимает ее закрепления, и картинка осталась бы в логе. Сервер такой просьбе отвечает 403 ("Убрать картинку из записи лога о вас может только другой модератор") и ничего не помечает |
| Прямой адрес формы, которую зрителю не дают (рекомендация) | Переход с заменой адреса туда, откуда к форме ведет ссылка (профиль) |

Признак "можно" считает сервер тем же кодом, которым потом откажет; пока признака нет, клиент повторяет правило сервера и называет в комментарии, какое. Форма комментария игры, блога, публикации и топика идет по `viewer.canComment` записи и дается только вошедшему. Признак отвечает тому, кто держал сессию при чтении: при входе из "Войдите, чтобы ..." и при выходе запись читается заново, а до ответа форма не предлагается. Плашка `closedHint` у DiscussionSection стоит раньше приглашения войти: гостю у обсуждения, где писать нельзя и после входа, стоит она, а не "Войдите". Так же идут "Создать топик" (`board.viewer.canCreateTopic`, гостю приглашение по `canCreateTopicAfterSignIn`), форма рецензии (`game.viewer.canReview`) и оценка поста (`post.viewer.canReview`, у каждого поста в любом списке). Окно трех дней у оценки на гонке отвечает 409 с фразой правила, а не 429. Так же идут и "Написать сообщение" в профиле (`profile.viewer.canMessage`), и поле переписки (`chat.viewer.canWrite`). О черном списке собеседника признак говорит ровно то, что сказал бы отказ первого сообщения: при выключенном "Блокировать личные сообщения" он остается "да". У чат-комнаты игры признака нет: страница повторяет правило записи сервера (`RoomIntentionResolver.SendMessage`) по строкам доступа комнаты и ролям в игре и называет его в комментарии `GameChatRoom.vue`. Это вторая копия правила, известное отступление до признака `viewer.canWrite` у комнаты.

Строка отказа под кнопкой остается только на гонку, когда положение изменилось между загрузкой страницы и нажатием. "Войдите, чтобы ..." у гостя не отказ, а путь, и стоит там, где вход открывает действие. Плашка обсуждения, которое читать можно, а писать нельзя, тоже не отказ нажатию: она говорит, почему под комментариями нет формы. Того же рода плашка под открытым чатом комнаты у того, кто его читает и писать не может. Вид у этих строк один, плашка DM2 (раздел "Empty State Standards", "Выравнивание"), и он отличает их от серой строки пустоты. Снятые строки и пропсы держит гейт `refusalCopy.spec.ts`; что запрет рисуется плашкой, а пустота серым и у этих строк нет своих отступов, держит `emptyStateAlignment.spec.ts`.

## Гейтинг гостя

Действия, требующие авторизации, **никогда не делают молчаливый редирект**.

| Сценарий | Паттерн |
|----------|---------|
| CTA-ссылка / подсказка "Войдите" | router-link, добавляющий `action: "login"` в query **текущего** маршрута — модал входа открывается на месте, фильтры и контекст сохраняются |
| Route guard (`requiresAuth`) | Редирект на главную с `?action=login` — гость сразу видит форму входа |
| Микродействия (лайк, голос) | Не рендерить для гостя |
| Счетчики "непрочитанного" | Гостю показываются нейтральные подписи ("Постов: N"), без слова "непрочитанных" |

Поддерживаемые значения query: `action=login | register | recovery`.

## Клавиатура и фокус

Кольцо фокуса на сайте одно: цвет `$link`, 2px, вплотную к контролу и по его форме. Второго цвета нет: серый `$border-focus` давал 2.85 на светлой странице при 3:1, которых WCAG 2.4.13 требует от индикатора фокуса, и в правилах фокуса больше не используется (гейт `focusRing.spec.ts` читает исходники и падает на любом другом цвете кольца). Отступ наружу тоже ушел: кольцо в двух пикселях от контрола читается как прямоугольник, нарисованный вокруг него, а не как его состояние. От нулевого отступа отступают ровно два случая, оба ниже.

| Требование | Реализация |
|------------|------------|
| Цвет кольца | Только `$link` (`--link`). Единственное исключение: речевой пузырь на зеленой заливке, где кольцо берет `$text-on-green`, потому что `$link` на зеленом контраста не дает |
| Поля ввода | На `:focus` рамка становится `$link`, и к ней вплотную кольцо `box-shadow: 0 0 0 1px $link`: итого 2px по форме поля, без outline. Рецепт один и для мыши, и для клавиатуры: в поле печатают, и отметка нужна обоим. Касается всего, что берет `+input-base` или рисует свою рамку поля |
| Блочные контролы | Кнопки, пилюли, вкладки, триггеры пикеров, ссылки-блоки, коробки с `tabindex`: `:focus-visible` дает `outline: 2px solid $link; outline-offset: 0`. Мышиный `:focus` без кольца через `:focus:not(:focus-visible)`. Прятать кольцо на голом `:focus` нельзя: `:focus-visible` входит в `:focus`, и клавиатура остается без отметки |
| Контролы вплотную к соседям | Строки таблицы, сегменты одной пилюли, ячейки сетки пикера, сообщения в ленте: `outline-offset: -2px`, кольцо внутрь, иначе оно ложится на соседа. Цвет тот же |
| Заливные главные кнопки | `outline-offset: 1px`: кольцо цвета заливки слилось бы с заливкой. Единственное место, где кольцо отходит от края, и зазор минимальный |
| Строчный текст | Текстовые ссылки, кнопки под ссылку (`+inline-link-button`, `+expand-toggle-button`), `span[tabindex]` с подсказкой: `outline: 1px solid $link; outline-offset: 2px`. Прямоугольник 2px вокруг слова тяжелее самого слова |
| Компоненты | Кольцо не подавляют и своего не изобретают: глобальное правило и миксины дают его сами. Свое кольцо рисует только контрол со своей рамкой поля, и рисует по рецепту полей |
| Кликабельные действия | `<button>`, а не `<a>` без `href` |
| Tooltips | Показываются и по фокусу с клавиатуры, не только по hover; фокус от касания или щелчка подсказку не открывает; на касании правило из CODE_STYLE.md, раздел Tooltips. Подсказка описывает контрол (`aria-describedby`, и только пока видима), но не дает ему имени |
| Декоративные иконки и разделители | `aria-hidden="true"` |
| Иконки-кнопки и числовые ссылки | Обязательный `aria-label` на самом контроле. Содержимое из одних символов ("<<", "...", "+") именем не считается |

## Выбор даты

Календарь поля даты (`CalendarGrid`), его месяцы и годы (`MonthYearGrid`), "Перейти к дате" в чате, панель периода в фильтре и пилюля периода статистики (`MonthYearPicker`) стоят такими, какими были до 5 октября (владелец, 12 октября 2026: "Верни как было"). Выбранный день, концы периода, месяц и год залиты главной кнопкой (строка "Выбор" выше). Календарь без даты открывается на сегодня или на дне, который назвало поле (`openOn`).

Сетка дней, месяцев или лет это одна остановка Tab. В днях стрелки ходят по дням и неделям, PageUp и PageDown листают месяц (с Shift год), Home и End ведут к концам недели, Enter и пробел выбирают. В месяцах и годах стрелки ходят по клеткам, вверх и вниз на ряд, Home и End к первой и последней, PageUp и PageDown листают год или блок лет. В календаре дней Escape на месяцах и годах возвращает к дням того месяца, что был на экране, и дальше не уходит: поле и окно вокруг календаря его не получают. Escape на днях закрывает календарь.

Поле даты (`DateInput`) высотой 38 на странице и 52 с текстом 15 в окне, как всякое поле; справа значок календаря, крестик очистки только там, где дату можно не заполнять (`clearable`). Набираются цифры, точки ставятся сами ("14031991" дает "14.03.1991"). Набранное, но не взятое остается в поле, и при уходе из него под полем встает красная строка 14 с причиной: "Такой даты нет", "Не раньше 05.10.2026", "Не позже 05.10.2026"; рамка не краснеет. Причина уходит, как только текст снова дата, и встает сразу, если граница сдвинулась под уже введенной датой. На касание поле открывает календарь без клавиатуры, второе касание закрывает календарь и дает цифровую клавиатуру. Пустой день рождения открывается на годах, на блоке текущий год минус двенадцать (2003-2014 в 2026).

Время (`TimeInput`) только набором: цифры, двоеточие ставится само ("2330" дает "23:30"), списка и значка нет; "25:00" не берется, причина "Такого времени нет". Дата со временем (`DateTimeInput`) это поле даты 148 и поле времени 72 в одну строку через 8, наружу строка "YYYY-MM-DDTHH:mm"; граница со временем называет момент целиком: "Не раньше 06.10.2026 05:30". Год (`YearInput`) четыре цифры, без стрелок и без сетки; причины "Год из четырех цифр", "Не раньше 2000", "Не позже 2100". Полей браузера `type="date"`, `"time"`, `"datetime-local"`, `"month"`, `"week"` в клиенте нет.

Ряд периода статистики (сегменты "Месяц | Год | Все время" и пилюля со стрелками) стоит одной строкой, где обе части помещаются; где нет, пилюля встает второй строкой под сегментами, вровень слева, через 8. Вбок ряд не листается, ни одна часть не обрезается. Держат `SiteStatisticsPage.spec.ts` и e2e `common/date-pickers.spec.ts`.

Панель периода в фильтре (`DateRangePicker`) стоит на `CalendarGrid` и `DateInput`. Держат `datePickers.spec.ts` (полей браузера нет), `dialogSurface.spec.ts` (поля в окне) и спеки `CalendarGrid`, `MonthYearGrid`, `MonthYearPicker`, `DateRangePicker`, `DateInput`, `TimeInput`, `DateTimeInput`, `YearInput`.

## Формат даты-времени

Полная дата-время отображается единообразно: **`DD.MM.YYYY в HH:mm`** (общий util, без локальных копий форматирования). Пустое значение печатается общим токеном (Table UX Standards выше).

**Записанное исключение:** полоса событий глобального чата для ближних дат использует компактный формат без года — `DD.MM` / `DD.MM в HH:mm` (by design: однострочная полоса, экономия места). Везде остальное действует полный формат.

## Empty State Standards

### Two-State Pattern

При наличии фильтров используем два разных сообщения:

| Состояние | Шаблон | Пример |
|-----------|--------|--------|
| Нет данных вообще | `{Genitive} пока нет` | "Игр пока нет" |
| Нет по фильтрам | `{Genitive} по заданным фильтрам не найдено` | "Игр по заданным фильтрам не найдено" |

**Код:**
```vue
{{ hasActiveFilters ? '{Items} по заданным фильтрам не найдено' : '{Items} пока нет' }}
```

### Компоненты

| Тип | Компонент | Когда |
|-----|-----------|-------|
| Таблица/список | `SecondaryText` | Простые списки |
| С иконкой | `EmptyState` | Центральный контент |
| Inline (dropdown) | `SecondaryText` | Внутри dropdown |

### Без фильтров

Если фильтров нет — только одно сообщение: `{Items} пока нет`

### Выравнивание

Пустые состояния и приглашения войти ("Войдите, чтобы создать игру") выровнены по левому краю, как обычный абзац. Центрирование текста и горизонтальное центрирование флекса в них запрещено. Вертикальная центровка внутри своего бокса допустима, как и центрирование самого спиннера в блоке загрузки.

Строка на месте формы говорит одно из двух, и вид у них разный. Запрет ("писать здесь нельзя", "Войдите, чтобы ...") стоит плашкой DM2 `RefusalNote` (`shared/ui/Layout`): бежевый фон `$bg-highlight-yellow`, рамка 1px dashed `$border`, без скругления, внутри отступ 5, текст 16 цветом текста, во всю ширину колонки, своих внешних отступов нет. `LoginPrompt` рисует ту же плашку со ссылкой "Войдите" цветом ссылки и держит 8 сверху и снизу. Пустота ("Комментариев пока нет", "Сообщений пока нет") остается серой строкой `SecondaryText`. Ни то, ни другое своего отступа слева не имеет и начинается ровно по краю колонки, как текст над ним; плашки обсуждения своих отступов не имеют вовсе, промежуток дает блок вокруг, "Комментариев пока нет" держит только 16 сверху. Гейт `emptyStateAlignment.spec.ts`, раздел "the lines that stand where a form would be": запрет рисуется только `RefusalNote` или `LoginPrompt`, пустота только `SecondaryText`, и у каждой строки свой набор сторон, где отступа быть не должно.

## Loading State Standards

### Skeleton-first подход

Предпочитаем skeleton'ы для улучшения perceived performance.

| Контекст | Компонент | Когда |
|----------|-----------|-------|
| Сайдбары | `SidebarSkeleton` | Списки ссылок |
| DataTables | `DataTableSkeleton` | Табличные данные |
| Профиль | `ProfileSkeleton` | Header профиля |
| Кнопки | `:loading` prop | Actions |
| Inline | `...` | Краткие индикаторы |

`:loading` у `Button` и у кнопки подтверждения в `ConfirmDialog` отключает контрол и рисует то же, что рисует отключенный: штриховку `+disabled-hatch` поверх его собственной заливки. Отдельного рисунка у ожидания нет — "сейчас недоступно" на экране говорится один раз; что контрол вернется, говорит `aria-busy`, и это не читает ни один стиль. Подпись не меняется: она называет действие, а не то, что происходит сейчас. Писать состояние в подпись ("Сохранение...", "Сохраняем...") запрещено: каждая страница выбирает для него свою формулировку, а кнопка меняет ширину посреди запроса и двигает соседнюю "Отмена". Замена подписи на `...` остается для построчных действий в списках.

### Геометрический паритет

Скелетон обязан быть геометрическим двойником контента, который встанет на его место: совпадают внешняя высота блока, вертикальные отступы, ширина контейнера и число строк-плейсхолдеров при типичном объеме контента. Расхождение видно как скачок верстки в момент подмены, и завышенная высота остается самой частой его причиной. Части контента, которых может не быть (бейдж, мета-строка), скелетон не рисует как обязательные.

Паритет проверяется, а не оценивается на глаз. По исходникам: контейнер (padding, margin, gap, min-height), высота строки и число повторов плейсхолдера против типичного числа строк контента. Живьем: `getBoundingClientRect().height` и computed-отступы у обоих состояний одного слота — скелетон-фазы и загруженной. Расхождение больше ~4px чинится в скелетоне под контент, не наоборот. Чистое устранение измеренного расхождения поштучного аппрува не требует (поручение владельца от 2026-07-13); все, что меняет вид скелетона сверх этого, идет через аппрув-каталог как обычно. Частые причины завышения: фиксированная `min-height` больше реального контента, лишние плейсхолдер-строки, свой `padding`, не совпадающий с контентным компонентом, и опциональные строки, нарисованные как обязательные.

### Когда использовать текст

Текст `"Загрузка..."` допустим когда:
- Контент переменной высоты (комментарии)
- Нельзя предсказать layout
- В модальных окнах

### Размещение и единичность

Skeleton живет рядом со своим компонентом-двойником (`DataTableSkeleton` в `shared/ui/DataTable`, `SidebarSkeleton` в `widgets/sidebar`), общие лежат в `shared/ui/Skeleton`. На одну загружаемую единицу — **один** skeleton-компонент в единственном числе (`ChatMessageSkeleton`, `GamePostSkeleton`, не `*Skeletons`); повторение под список делается через проп `:count`, а не отдельным компонентом. Дубли одного skeleton по разным слоям запрещены.

### Shimmer animation

Все skeleton'ы используют единую shimmer-анимацию:
- Duration: `$loading-tempo` (1.5s) — один темп на все ожидания сайта
- Easing: ease-in-out / infinite
- Background gradient: `$bg-element-hover` → `$bg-element`

**SASS mixin:** `+skeleton-shimmer` в `_Skeleton.sass`

## Титул вкладки и теги превью

Титул вкладки собирается одним форматом: различающий сегмент первым, бренд последним, разделитель " | ". Тем же знаком разделяются внутренние сегменты, а порядок в зонах — сущность, потом секция: браузер режет титул справа, поэтому первым стоит то, что отличает вкладку от соседней.

Статический head документа (`index.html`) — сайтовая личность по умолчанию. Пока рендера на сервере нет, один и тот же head уходит на любой адрес: краулер и превью ссылки в мессенджере читают именно его, а не титул, который бандл ставит после загрузки. Отсюда правила. В статическом head держатся только сайтовые истины: заголовок, описание и картинка превью по одному экземпляру. Описание одно на поиск и на превью. Заголовок собран тем же форматом, что и титул вкладки, и совпадает с титулом корня. Значения, привязанные к адресу (адрес страницы, canonical, название игры или топика), в статический head не заводятся — на всех страницах, кроме одной, они лгут. Они появляются вместе с рендером на сервере или пререндером, и тогда статический head остается для них значением по умолчанию, а не вторым независимым списком.
