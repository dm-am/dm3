# DM3 — Прогресс реализации

Спутник к [Документация_по_разработке_DM3.docx](Документация_по_разработке_DM3.docx)
(полный план). Здесь — функциональная полнота и инвентарь страниц, разложенные по
ярусам доступа: в этом порядке функционал открывается тестировщикам.

**Статус зоны — одна отметка.** Состояния идут по возрастанию готовности и
исключают друг друга:

| Отметка | Значит |
|---------|--------|
| ⬜ | не начато |
| 🟡 | частично: часть зоны работает, часть нет — что именно, сказано в заметке |
| 🔎 | построено и покрыто тестами, владелец глазами не смотрел |
| ✅ | построено и осмотрено владельцем |

Зеленые тесты сами по себе ✅ не дают. Между 🔎 и ✅ стоит живой осмотр, потому
что верстку, текст и поведение на экране автотесты не судят — этот класс
дефектов ловится только глазом.

## Порядок запуска

Полный план перехода — раздел 7 docx, шесть этапов. Ярусы ниже — внутренняя
структура только первого из них: базовое тестирование силами разработчиков и
модерации на чистой сидовой базе. Альфа и бета тестируют сайт целиком, уже на
копии базы DM2.

```mermaid
flowchart TB
    s1["Этап 1 — MVP<br/>тест силами разработчиков и модерации,<br/>чистая база; по итогам — набор в альфу"]
    s2["Этап 2 — закрытый альфа-тест<br/>волонтеры из DM2, копия базы DM2,<br/>канал в Дискорде"]
    s3["Этап 3 — доработка до функционала DM2<br/>сравнение с DM2, добор функций,<br/>параллельный тест альфа-тестерами"]
    s4["Этап 4 — публичный бета-тест<br/>свежая копия базы DM2,<br/>открытый вход для всех желающих"]
    s5["Этап 5 — финальная подготовка<br/>доработки + стресс-тест на последней<br/>копии данных DM2"]
    s6["Этап 6 — замена DM2<br/>полная миграция базы, редирект,<br/>отключение и архивация DM2"]
    s1 --> s2 --> s3 --> s4 --> s5 --> s6
```

Перед каждым тестовым этапом база DM3 очищается и заменяется актуальной копией
DM2 — тестовые данные не накапливаются. Ни один этап не начинается, пока не
закрыты критические ошибки предыдущего.

### Этап 1 изнутри: ярусы доступа

Внутреннее тестирование идет ярусами: сначала все, что видит гость, затем то,
что открывает вход, затем модерация и администрирование. Ярус не считается
сданным, пока по нему не прошли живые люди.

```mermaid
flowchart LR
    G["Ярус 1 — Гость<br/>страницы без входа<br/>+ отказы"] --> U["Ярус 2 — Пользователь<br/>свои страницы<br/>+ гостевые заново"]
    U --> M["Ярус 3 — Модерация<br/>свои страницы<br/>+ нижние заново"]
    G -.->|"живой проход"| G2["Правки по фидбеку яруса 1"]
    U -.->|"живой проход"| U2["Правки по фидбеку яруса 2"]
    M -.->|"живой проход"| M2["Правки по фидбеку яруса 3"]
```

Ярус — это набор проверок, а не набор страниц. Проверка — пара "страница плюс
роль": одна и та же комната для гостя это текст, для игрока — форма письма,
броски и оценки чужих постов, для модератора — правка любого поста. Поэтому
ярус состоит из двух частей: страницы, которые на нем открываются впервые, и
повторный осмотр страниц нижних ярусов, чей опыт на этом ярусе меняется.
Инвентарь ниже перечисляет первую часть, разделы "Повторный осмотр" — вторую.

Впервые страница открывается там, где ее пускает гейт маршрута: ярус 2 — это
`requiresAuth` в `app/providers/router.ts`, ярус 3 — `requiresAuth` плюс
поддерево `/moderation` (флаг `moderationZone` включает сайдбарную панель,
маршрут он не закрывает).

Часть страниц открыта маршрутом, но закрыта внутри компонента: гость, открывший
настройки игры, видит отказ, а не форму. Такие помечены в инвентаре, и на первом
ярусе у них осматривается ровно один экран — сам отказ: внятен ли он, не торчит
ли под ним часть формы, предлагает ли войти. Содержимое этих страниц смотрится
на том ярусе, где роль зрителя его открывает.

## Гейты

Числа тестов и объемы сида здесь не хранятся: они меняются с каждой правкой и
устаревают быстрее документа. Что гонять до пуша и в каком порядке, знает
`scripts/hooks/pre-push`, там же сказано, какие джобы воркфлоу оставлены за CI.
Текстовые правила (буква "е", кавычки, разделители) держат тесты фронта, а не
строка в этом документе.

Страницы без входа с сайта, открываются только адресом:

- `/subscriptions`, подписки.
- `/notepad`, личный блокнот (заметки игры и блога при этом линкуются из
  панелей).

Частично:

- `/game/:id/post-reviews`: фильтра по комнате нет, запрос постов комнату не
  принимает.
- Страницы ошибок: отдельных иллюстраций для 404, 409 и 410 нет, стоит общая
  (план в ERROR_PAGES_AND_LORE.md).

Только сервер, клиента нет:

- Поиск по форуму (`GET /v1/search/forum`).
- Самоназначение наставника на игру и блог (`/v1/moderation/{games,blogs}/{id}/mentor`).
- Модераторы разделов форума и смена роли пользователя администратором
  (`/v1/boards/{id}/moderators/{username}`, `/v1/moderation/users/{username}/role/{role}`).
- Статистика обращений модератора, обращение от имени
  модератора (`/v1/moderation/tickets/stats`, `POST /v1/moderation/tickets`).

Только план (ROADMAP.md): многоразовые ссылки-приглашения, вход через Google.

## Остаточные зазоры

- Комментарии к публикации не помечаются прочитанными: у обсуждения блога
  эндпоинт для этого есть, у публикации нет, поэтому счетчик непрочитанного
  снимается только на обсуждении блога.
- Три сид-блога с placeholder-publicId (`t...`) из внешнего сид-пути: работают,
  но неканонично, лечится реседом.
