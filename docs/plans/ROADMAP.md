## Рассматривается

| Задача | Описание |
|--------|----------|
| k3s + Helm + Terraform | Kubernetes, когда появится второй ВЫЧИСЛИТЕЛЬНЫЙ узел в одном периметре доверия. Точка присутствия узлом кластера не становится никогда: она намеренно не знает секретов, а узел k3s их получает (аудит стека 2026-08-24) |
| Centrifugo | Отдельный realtime-сервер, когда realtime станет самостоятельной нагрузкой (десятки тысяч соединений, независимое масштабирование канального слоя). Миграция дешевая по построению: границей служит RabbitMQ-контракт RealtimeNotification, SignalR-специфика изолирована в двух классах API и двух файлах клиента (аудит 2026-08-24) |
| Dependabot | Робот, создающий заявки на обновление зависимостей по расписанию и сразу при находке уязвимости. Настройка уже написана и лежит в репозитории: группы обновлений и потолок открытых заявок, чтобы поток был обозримым; включение - переключатель в настройках репозитория. Не включен намеренно: пока стек двигают вручную и часть версий прижата осознанно, робот предлагал бы сдвинуть ровно эти пины и спорил бы с идущей работой. Условие включения - завершение разработки сайта. Тот же рубеж, что у нормальных миграций базы: пока идет разработка, поток заявок это мусор, который потом придется убирать, а после нее невидимое старение зависимостей становится риском с часами |
| Звездочка как элемент списка | `[*]` как форма элемента списка в BBCode, рядом с `[li]`. Отложено решением владельца: это не починка неправильного поведения, а новое написание. Переносимому корпусу оно не нужно - списки там написаны через `[li]`, - а тем, кто пишет руками, ту же работу делают кнопки редактора. Условие возврата: если окажется, что люди спотыкаются, набирая списки руками. |
| Google OAuth | Вход через Google |
| Автоприветствие наставника | Приветственное сообщение новичку от назначенного наставника |

## Разбор пользовательской разметки

Парсер BBCode лежит в репозитории и правится как наш код. Ниже - работа,
которую это открыло.

| Задача | Состояние |
|--------|-----------|
| Перестройка разбора: именованные свойства тегов, политика по дереву | Не начата; целевое правило - в [BBCODE_RENDERING.md](../architecture/BBCODE_RENDERING.md). Первый заход неделим: грамматика, кодирование значения по позиции записи и тотальность скрытой разметки идут одним коммитом, порознь они открывают окно между правками |
| Дерево наружу и политика проходом | Второй заход и последнее обязательное условие остальных: узлы читаются и строятся снаружи, видимость приватного блока и правила аудиторий переезжают в проход, вывод становится чистой функцией дерева. Дальше порядок свободен, кроме одного: текстовая проверка сбалансированности не снимается раньше своей замены по дереву |
| Теги адреса в грамматику | Картинка, ссылка и упоминание объявляются обычными тегами с объявленными атрибутами; уходят плейсхолдеры, служебный маркер, вырезание и возврат кусков текста и весь серверный порядок проходов |
| Каталог тегов как единственный источник | Одно объявление тегов, атрибутов и доступности по поверхностям, из которого берут наборы сервера, манифест клиента, список валидатора и состав тулбара |
| Производные представления из дерева | Большая часть сделана: колонку видимого текста пишет путь сохранения, отбор постов идет по ней. Осталось снять два выражения приватного блока над этой уже очищенной колонкой |
| Остаток находок парсера | Независимые закрыты. Оставшиеся меняют вид и ждут построчного аппрува владельца |
| Интерфейс второго фактора | Сделан целиком. Открыто одно решение владельца: какие оповещения о втором факторе слать письмом. Сегодня писем два, и оба несут ссылки, без которых почтового пути снятия не существует; остальные события журнал показывает в истории безопасности |
