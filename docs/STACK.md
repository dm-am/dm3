# Технологии DM3

Строка технологии: название, версия, что это и зачем у нас. Под ней, где выбор не
очевиден, альтернативы и довод против них. Версии точные, их сверяет с
манифестами сборки архитектурный тест: имя в обратных кавычках обязано быть
пакетом, образом или действием из манифестов, а версия рядом с ним совпадать с
установленной. Имя с ".*" или "/*" на конце обозначает группу пакетов с общим
префиксом. Пункт со словами "в плане" описывает то, чего еще нет.

Стек DM2, старого живого сайта, описан отдельно в [STACK_DM2.md](./STACK_DM2.md).

## DM3

### Платформа

- `.NET SDK` 10.0.100, платформа .NET 10 LTS, веб-слой на ASP.NET Core. SDK
  закреплен в пределах 10.0.
- `C#` 14.0, версия языка задана явно, чтобы код собирался одинаково у
  разработчика и в CI.
- `mcr.microsoft.com/dotnet/sdk` 10.0 и `mcr.microsoft.com/dotnet/aspnet` 10.0,
  образы сборки и запуска серверных хостов.

### Веб-слой

- Kestrel и ASP.NET Core: API, хаб уведомлений, проверка origin изменяющего
  запроса, ограничение частоты запросов.
- `Swashbuckle.AspNetCore.*` 10.2.3, документ API и страница Swagger.
- `AspNetCore.HealthChecks.*` 9.0.0, проверки готовности PostgreSQL и RabbitMQ.
- `Microsoft.Extensions.*` 10.0.11: конфигурация, опции, контейнер зависимостей,
  логирование, кэш в памяти, хостинг.
- Встроенный контейнер зависимостей: явные регистрации плюс скан сборки по
  конвенции, полнота регистраций проверяется при старте.
  Альтернативы: Autofac. Почему не он: второй язык регистрации без выигрыша.

### Доменная логика

- `FluentValidation` 11.9.2, проверка бизнес-правил в доменных модулях.
- `Riok.Mapperly` 4.3.1, генератор мапперов DTO на компиляции: несведенное поле
  ломает сборку, а не запрос.
  Альтернативы: AutoMapper. Почему не он: маппинг в рантайме, пропущенная карта
  отвечала 500. Ветка 15.0 стала коммерческой.
- `Polly` 8.4.1, повторы при обработке сообщений и объявлении обмена брокера.
- Разбор BBCode: чужая библиотека, которая держится в дереве проекта отдельной
  сборкой, наши правки в ней подписаны в коде.
  Альтернативы: пакет NuGet. Почему не он: единственный релиз без исходников и
  лицензии, а разбор пользовательского текста приходится править.

### Учетные записи и криптография

- `Konscious.Security.Cryptography.Argon2` 1.3.1, хеш паролей Argon2id.
  Альтернативы: PBKDF2. Почему не он: Argon2id за счет требований к памяти
  устойчивее к перебору на GPU.
- `Otp.NET` 1.4.1, арифметика RFC 6238 и Base32 для второго фактора.
- `uqr` 0.1.3, QR-код второго фактора рисует сам клиент.
  Альтернативы: внешний сервис QR. Почему не он: в ссылке otpauth лежит общий
  секрет целиком.
- `BouncyCastle.Cryptography` 2.7.0, проверка подписи Ed25519 у взаимодействий
  Discord: в BCL до .NET 10 включительно Ed25519 нет.

### Данные

- `postgres` 16, PostgreSQL как единственная СУБД. Формы, которые читаются и
  пишутся целиком (схема атрибутов, метаданные уведомления, результат броска),
  лежат в jsonb, остальное в таблицах.
  Альтернативы: вторая, документная СУБД (часть данных жила в MongoDB). Почему
  не она: между хранилищами нет ни транзакции, ни соединения таблиц, а два
  ночных бэкапа не дают согласованного снимка.
- `Microsoft.EntityFrameworkCore.*` 10.0.11 и `Npgsql.EntityFrameworkCore.PostgreSQL`
  10.0.3, EF Core с провайдером Npgsql, один контекст на все модули. Провайдер в
  памяти только для тестов.
- Полнотекстовый поиск на tsvector той же PostgreSQL, приватные блоки разметки в
  индекс не попадают.
  Альтернативы: отдельный поисковый движок (прежде Elasticsearch). Почему не он:
  права доступа меняются на ходу, и индекс обязан совпадать с ними.

### Очереди сообщений

- `rabbitmq` 4.3-management, брокер доменных событий между модулями и воркерами.
- `RabbitMQ.Client` 7.2.2, официальный клиент и свой тонкий слой: публикация
  через транзакционный outbox в PostgreSQL, доставка хотя бы один раз,
  потребители идемпотентны.
  Альтернативы: шина общего назначения, обертка Jamq. Почему не они: шина
  приносит свой конвейер без выигрыша на нашем числе воркеров, обертка держалась
  на одном авторе и застряла на клиенте 6.x.

### Файловое хранилище

- `chrislusf/seaweedfs` 4.48, образ закреплен по дайджесту, S3-совместимое
  объектное хранилище для байтов загруженных файлов в режиме одного процесса.
  Записи о файлах в PostgreSQL. Бакет, учетки и публичное чтение задает скрипт
  старта. Предел памяти сборщика держит пик ниже лимита контейнера ценой работы
  сборщика в покое.
  Альтернативы: MinIO, Garage, RustFS. Почему не они: свободные образы MinIO
  больше не раздаются, у Garage нет правил доступа по префиксам, RustFS просит
  от 2 ГБ памяти.
- `nginx` 1.27.5-alpine, образ закреплен по дайджесту, единственный вход в
  объектное хранилище: пропускает к нему S3 и метрики и ничего больше.
- `AWSSDK.S3` 3.7.400.5, клиент S3 в приложении.
- `darthsim/imgproxy` v4.0.14, варианты изображений на лету по подписанному
  адресу.
- `SixLabors.ImageSharp` 3.1.11, разбор загруженной картинки: уменьшение,
  минимальный размер аватара, защита от бомбы распаковки.

### Резервное копирование

- pg_dump ночью с заданным сроком хранения. Зеркало бакета хранилища отдельным
  ночным заданием. Проверка снимков той же ночью.

### Защита

- Вход по HttpOnly-куке (BFF), пароль проверяется по базе утечек, второй фактор
  приложением-аутентификатором с резервными кодами.
- Разметку пользователя в HTML превращает только сервер, сверху Content Security
  Policy. Куки SameSite=Lax и отказ изменяющему запросу с чужим origin.
- Ограничение частоты запросов, временная блокировка после неудачных входов,
  скрытые поля-ловушки против ботов, журнал событий безопасности.

  токенов, единая библиотека Vue-компонентов.
