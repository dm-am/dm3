# Глоссарий терминов

Здесь только те термины, которые нельзя однозначно прочитать в коде: неоднозначные, пересекающиеся или спорные имена. Члены доменных перечислений и их русские подписи живут в коде (`DM.Domain.Core/Enums`), права ролей — в [AUTHORIZATION.md](../architecture/AUTHORIZATION.md).

**Правило именования:** у термина одно русское слово и один английский идентификатор, одинаковые во всех слоях — UI, код, CSS, документация. Синонимы не вводятся.

> **Контекстуальные термины:** Comment, Like, Message, Discussion, Invitation, Blacklist, Notepad повторяются в разных модулях. Каждый модуль имеет свою реализацию этих сущностей.

---

## 1. Модуль, игра, блог

| Код | Русский | Описание |
|-----|---------|----------|
| Module | Модуль | Игра или блог — основные контентные единицы сайта. Общее у обоих: статус, видимость черновика, премодерация, ассистенты, наставник, блокнот, черный список, приглашения, обсуждение |
| Game | Игра | Текстовая ролевая игра: комнаты, персонажи, посты, броски кубиков |
| Blog | Блог | Личное пространство пользователя для публикаций: рубрики и публикации |

Единица контента в каждой поверхности называется своим словом, и эти слова не взаимозаменяемы:

| Поверхность | Единица контента |
|-------------|------------------|
| Игровая комната | Post — игровой пост |
| Чат-комната игры, переписка, глобальный чат | Message — сообщение |
| Блог | Publication — публикация внутри Rubric |
| Форум | Topic — топик внутри Board |
| Обсуждение любого из перечисленного | Comment — комментарий |

### Персонажи
| Код | Русский | Описание |
|-----|---------|----------|
| PC | Персонаж игрока | Персонаж, управляемый игроком (Player Character) |
| NPC | Персонаж мастера | Персонаж, управляемый мастером (Non-Player Character) |

## 2. Наставник — три разные роли

Одно слово, три несвязанные роли. В коде и документации всегда уточнять, какая имеется в виду.

| Код | Русский | Описание |
|-----|---------|----------|
| Mentor (UserRole) | Наставник сайта | Глобальная роль: опытный пользователь, помогающий новичкам |
| Mentor (GameRole) | Наставник игры | Куратор одной конкретной игры. Не ведущий: ведущие игры — это Master + Assistant |
| Mentor (BlogRole) | Наставник блога | Куратор одного конкретного блога: премодерация публикаций, доступ к черновику и к блокноту блога. Настройки блога ему недоступны |

## 3. Два вида бана

Слово "бан" без уточнения неоднозначно, и охват у них разный.

| Код | Русский | Описание |
|-----|---------|----------|
| DemocraticBan | Демократический бан | Основной. Глушит публичную речь: глобальный чат, форум, обсуждение чужих игр и блогов. Свое остается открытым, посты в комнатах и личные сообщения не затронуты |
| FullBan | Полный бан | Редкий. Запрещает отправлять все и не пускает даже войти |

Полный контракт — в [AUTHORIZATION.md](../architecture/AUTHORIZATION.md).

## 4. Отзывы — четыре независимые сущности

> **Важно:** Система отзывов состоит из 4 НЕЗАВИСИМЫХ сущностей (не unified Review).

| Код | Русский | Контент | Тональность |
|-----|---------|---------|-------------|
| UserEndorsement | Рекомендация | Простой текст, без BBCode | Только положительная |
| WebsiteTestimonial | Отзыв о сайте | Простой текст, без BBCode | Только положительная |
| GameReview | Рецензия на игру | BBCode | Любая |
| PostReview | Оценка поста | BBCode + Sign (+1 / 0 / -1) | Любая |

| Код | Русский | Описание |
|-----|---------|----------|
| Rating | Рейтинг | Соотношение суммы оценок постов пользователя и количества постов (X/Y) |

## 5. BBCode Rendering

| Термин | Описание |
|---|---|
| **BBCode** | Разметка пользовательского контента в формате `[tag]content[/tag]`. Источник истины на клиенте — всегда BBCode (именно он отправляется на сервер на сохранение). |
| **Render authority** | Сервер — единственный renderer BBCode для display-путей. Клиент никогда не рендерит пользовательский BBCode для чтения. |
| **Surface** | Семантическая поверхность контента (GamePost / Comment / GlobalChatMessage / Profile / DirectMessage). Определяет, какие теги разрешены. |
| **Audience** | Намерение рендера: `display` (обычное чтение), `author_edit` (автор редактирует свой контент), `plain_text` (email), `embed_safe` (link preview). Передается в заголовке `X-Dm-Audience`. |
| **`[private]`** | Privacy-тег в игровых постах, адресуемый к конкретным PC-персонажам. Виден адресатам, автору поста, ведущим игры (master + assistants). Moderator+ НЕ видит. |
| **`[mod]`** | Визуальный блок "речь от модерации" в surface Comment (включает тела топиков форума) и GlobalChatMessage. Виден всем, включая гостей; ограничение — на запись. |
| **Game lead (ведущий игры)** | Master + Assistant игры. Наставник НЕ является ведущим. Ведущие видят все `[private]` блоки в игре автоматически. |
| **Author-forever** | Автор поста всегда видит свои `[private]` блоки, даже если он больше не активен в игре. |
| **Addressee-forever** | Владелец персонажа-адресата всегда видит приватный текст, адресованный его персонажу, даже если персонаж больше не активен в игре. Работает через snapshot, зафиксированный при сохранении поста. |
| **SharePrivateWithAll** | Per-post настройка: автор помечает весь `[private]` контент поста как видимый всем читателям комнаты. |
| **ViewPrivateText** | Per-room настройка: все участники комнаты видят весь `[private]` текст постов этой комнаты. |
| **Author-edit round-trip** | Асимметричный контракт редактора: при загрузке сервер возвращает HTML с `data-bb-*` атрибутами, при сохранении клиент шлет BBCode. |

Полный контракт — в [BBCODE_RENDERING.md](../architecture/BBCODE_RENDERING.md).

## 6. Верстка сообщений (MessageLayout)

Верстка сообщений, постов, комментариев и топиков. Future-proof union-тип: новые значения добавляются без рефакторинга API.

| Код | Русский | Описание |
|-----|---------|----------|
| MessageLayout | Верстка | Настройка компоновки сообщений (frontend-only, хранится в localStorage ключом `dm_message_layout`) |
| `compact` | Компактная | Без аватаров, плотная компоновка — подходит для длинных лент |
| `full` | Полная | С аватарами, развернутая компоновка — дефолт для новых пользователей |

**Терминология** (единая во всех слоях — UI, код, CSS, документация):
- **Название фичи:** `Верстка` / `MessageLayout` — не "отображение" / "display", не "режим" / "mode"
- **Опции:** `компактная` / `compact`, `полная` / `full` — не "обычное" / "normal"
- **Store API** (`@/shared/stores/ui`): `messageLayout`, `isCompactLayout`, `setMessageLayout(layout)`
- **Компонентный prop** (leaf-уровень): `compact: boolean` — бинарный флаг "скрыть аватар"
- **CSS-классы:** `.layout-compact` (wrapper), `.compact` (leaf, по prop)
