# Стенд кадров и снимок ответов API

Как кадрами страниц и снимком ответов API доказать, что правка невидима. Не проверяется: инструмент вне CI и без своих тестов.

По умолчанию инструмент меряет уже запущенный стенд, тот, с которым работает сайт
на 5173, и ничего в нем не сбрасывает, не пересобирает и не сеет, а docker только
спрашивает. В CI не входит, потому что пиксели зависят от шрифтов и растеризатора
машины: базу сравнивают только там, где ее сняли, и в репозиторий она не кладется.

## Команды

Из корня репозитория:

```
node scripts/visual/visual.mjs stand
node scripts/visual/visual.mjs snap <метка> [--rev REV] [--root DIR] [--theme dark]
node scripts/visual/visual.mjs diff <метка> [--rev REV] [--root DIR] [--theme dark]
node scripts/visual/visual.mjs api-snap <метка> [--rev REV] [--root DIR]
node scripts/visual/visual.mjs api-diff <метка> [--rev REV] [--root DIR]
```

`stand` проверяет стенд и печатает его отпечаток, `snap` снимает базу, `diff`
сравнивает с ней. Коды: 0 совпало, 1 есть разница, 2 отказ до прогона, 3 прогон
недействителен (причины в разделе "Когда что-то не сходится").

## Как снять базу

Стенд поднят и засеян (`dm.ps1 start`, `dm.ps1 seed`), лимиты запросов выключены
командой `dm.ps1 e2e`, она пересоздает только API, данные остаются. Без docker
лимиты не прочитать, и тогда вместо отказа предупреждение. Порядок шага описан в
скилле [refactor-in-bounds](../../.claude/skills/refactor-in-bounds/SKILL.md).
Для правки сервера API между `snap` и `diff` пересобирается из дерева той же
`dm.ps1 e2e`, иначе снимок спрашивает прежний сервер.

`--rev` (он же `--commit`) собирает клиент из коммита, выгруженного `git archive`:
рабочее дерево общее, и чужая временная правка исходника (прогон "тест падает на
сломанном") попала бы в сборку. Сервер при этом тот, что запущен (кроме
`--rebuild-stand`). Клиент собирается в свой каталог (`dist/` не трогается) и
поднимается `vite preview` на 5174, порт должен быть свободен: API в разработке
пускает браузер только с 5173 и 5174.

`--no-build` берет прошлую сборку клиента. `--grep RE` ограничивает состояния или
маршруты API. Такой прогон сравним с полной базой только по состояниям гостя,
остальные оставляют следы (открытый топик становится прочитанным).

## Отпечаток данных и пересев

`meta.json` базы хранит отпечаток данных стенда: итоги `GET /v1/stats` и дату
регистрации опорного аккаунта сида (`SEED_ANCHOR` в `visual.mjs`). Новая игра,
пост или аккаунт сдвигают итог, пересев сдвигает дату. Отпечаток сверяется до
прогона (не совпал, и это код 2, базу снимают заново с той же меткой) и после
(изменился, и это код 3).

## Шум запущенного стенда

Отпечаток не видит следов самого прогона: входов ролей и прочитанного. Первый
прогон после сида видит непрочитанное, следующие уже нет, поэтому первый `snap`
после сида пробный, а базой служит второй. Строки входов (сеансы, журнал
безопасности) и порядок аккаунтов стенда в списках по активности сворачивает
`api-volatile.mjs`. Расходится то, что делали на сайте между базой и сравнением,
если итоги не сдвинулись. Вердикт без этого шума дает только пересобранный стенд.

## Пересобранный стенд: --rebuild-stand

Флаг уничтожает данные общего стенда и выключает сайт на 5173 на 10-15 минут,
перед этим инструмент ждет 10 секунд, Ctrl+C отменяет. Порядок пересборки
записан в `rebuildStand` в `visual.mjs`: API и воркеры стоят, пока сид с
закрепленными эпохой и зерном пишется в пустую базу, потому что их периодические
задачи посреди сида сдвигали идентификаторы. Два прогона одного коммита на таком
стенде дают одинаковые байты. База с флагом сравнима только с прогоном с флагом,
и наоборот. `stand --rebuild-stand` только пересобирает стенд. С `--rev` из
коммита собирается и стек, а не только клиент.

## Где что лежит

Базы в `%TEMP%/dm3-visual/frames/<метка>/<тема>/` и `%TEMP%/dm3-visual/api/<метка>/`,
другое место задает `--root`. Отчет `diff` рядом в `<метка>.diff/`: `report.txt`,
кадры `-actual` и `-diff`, для дерева и стилей файлы `.actual` и `.diff`.

## Что снимается

Кадры: состояния из `states.ts` от ролей из `roles.ts`, размеры окна в
`frames.config.ts`. Три канала: PNG без единого отличного пикселя (с допуском в
единицу канала на сглаженный край), дерево DOM и вычисленный стиль ключевых узлов.
Часы страницы стоят на закрепленной эпохе (`SEED_EPOCH`), и на запущенном стенде
тоже: его сид разложен от другого дня, но базе и сравнению важно, что часы одни.
Случайность закреплена, интернет отключен, перед съемкой дерево должно простоять
без изменений. Все это в `capture.ts` и
`frames.spec.ts`.

API: все GET из `artifacts/openapi-routes.json` от гостя, участника и модератора,
параметры пути заполняет `api-fixture.mjs`. Маршрут, который он не заполнил,
выводится строкой `NOT ASKED`, и прогон завершается кодом 1.

## Маски и изменчивые поля

Что меняется между прогонами одного коммита и не закрепляется, внесено с причиной
в `masks.ts` (кадры), `api-volatile.mjs` (поля ответов) и `unordered.mjs` (списки,
которые сервер отдает без порядка). Запись прячет изменения этого места, поэтому
появляется, только когда закрепить не вышло. Записи `unordered.mjs` описывают
дефекты сервера и уходят вместе с ними.

## Когда что-то не сходится

- `BROKEN`: состояние не открылось, править `states.ts` или код. С 429 значит
  включенные лимиты.
- `DIFFERS`: смотреть `-diff.png` и `.diff` рядом с отчетом.
- Код 2: стенд не отвечает или не засеян, включены лимиты, база снята в другом
  режиме или на других данных.
- Код 3: во время прогона стенд пересоздали (`dm.ps1 e2e` или `reset`,
  `verify-seed-reproducibility.sh`), изменились его данные, API ответил 429
  снимку ответов, либо в дереве записали исходник, из которого шла сборка (без
  `--rev`).
  Стенд и дерево общие, на время прогона их никто больше не трогает.
