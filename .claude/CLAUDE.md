# DM3

Платформа для текстовых ролевых игр, модульный монолит на Clean Architecture.
Документы перечислены в [README.md](../README.md), структура кода в
[PATTERNS.md](../docs/conventions/PATTERNS.md), порядок работы и скиллы в
[PROCESS.md](../docs/conventions/PROCESS.md).

Документация по-русски, код и комментарии по-английски. Русский текст по
[CODE_STYLE.md](../docs/conventions/CODE_STYLE.md), раздел "Русский текст".

## Git без потерь

Команды, теряющие несохраненную работу, блокирует хук, перечень в `RULES`
файла [block-dangerous-git.js](hooks/block-dangerous-git.js). Ветка создается
`git switch -c` или `git worktree add`.

Файл возвращается из истории командой `git show <ревизия>:<путь> > <путь>` в
Git Bash (инструмент Bash), не в PowerShell: там файл выходит в UTF-16 с BOM.
Соседние правки целы. `git stash` прячет все дерево с правками параллельных
агентов: агенту он запрещен, главной сессии допустим, только когда параллельной
работы нет, иначе спросить владельца.

## Миграция одна

Только `InitialCreate`, изменения схемы вносятся в нее, новую миграцию блокирует
хук [block-new-migrations.js](hooks/block-new-migrations.js). Конец правила
описан в [DATA_STORAGE.md](../docs/conventions/DATA_STORAGE.md), раздел "Миграции".

## Правила работы

- Видимое меняется только по поштучному аппруву владельца: каталог правок до
  реализации, починка не исключение. Граница видимого в PROCESS, раздел
  "Видимые изменения идут через аппрув".
- В dev только веткой и PR, squash одним коммитом без соавторства, прямых
  пушей нет. Связанное одной веткой, несвязанное по веткам. Тело PR
  перечисляет изменения из диффа, а не намерения.
- Модель агента выбирается по типу работы и называется в задании и в отчете.
  Главная сессия (план, ответы владельцу, решения) на самой сильной модели.
  Код с логикой и ревью Opus, безопасность и устройство модулей Fable
  точечно, механика по готовому списку (удаление, переносы, прогоны, кадры,
  листы) Sonnet, чтение и сбор Haiku. Глубина мышления: код medium, ревью
  и безопасность high, главная max, простое ниже. Дважды не прошедшая
  проверку дешевая модель отдает задачу Opus. Смена модели без строки в
  задании запрещена.
- Документ пишет правило и ссылку, а не копию и не снимок: перечни файлов,
  имена классов, числа и даты устаревают с первой правкой. Код важнее
  документации: в документ идет только то, чего из кода не узнать.

## Что чаще всего пропускают (доводы в PROCESS)

- Проектный документ проходит несколько кругов свежих ревьюеров, две рамки
  (безопасность с корректностью, соразмерность с ценой) у разных агентов.
- Проверенное несет доказательство на месте, непроверяемое помечено или удалено
  вместе с доводом.
- Тест обязан упасть на сломанном коде, это проверяется прогоном. Вердикт гейта
  по коду возврата, а не по хвосту вывода.
- Видимое человеку закрывается живым стендом, тесты его не ловят.
- Агент правит свою зону файлов, прогоны идут по очереди, коммитит оркестратор
  по именам файлов.
