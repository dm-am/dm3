## Запрещенные команды (hooks блокируют автоматически)

НИКОГДА не использовать:
- `git checkout` — теряет незакоммиченные изменения
- `git reset --hard` — теряет незакоммиченные изменения
- `git clean -fd` — удаляет untracked файлы
- `git stash drop` — теряет stash

Полный перечень, с эквивалентами (`git restore`, `git clean -f`) и другими командами,
теряющими работу (`push --force`, `branch -D`), — `RULES` в [block-dangerous-git.js](hooks/block-dangerous-git.js).

**Для отмены изменений:** вернуть файл командой `git show <ревизия>:<путь> > <путь>`
в Git Bash (инструмент Bash), не в PowerShell: там файл выходит в UTF-16 с BOM.
Соседние правки при этом целы. `git stash` (без drop) прячет все дерево разом,
вместе с правками параллельных агентов: агентам он запрещен, главной сессии
допустим, только когда параллельной работы нет. Иначе спросить пользователя.

## Миграции

Только одна миграция `InitialCreate`. Изменения схемы вносить в нее, не создавать новые.

Правило держится на том, что боевой базы не существует: схема накатывается
ресетом. Оно заканчивается в день, когда появятся данные, которые нельзя
потерять — триггер и порядок перехода описаны в
[DATA_STORAGE.md](../docs/conventions/DATA_STORAGE.md).
</critical_rules>

## Правила работы

- **Визуальные изменения — только по поштучному аппруву.** Каталог предлагаемых
  правок владельцу до реализации; функциональное и невидимое можно без него.
  Починка исключением не является: она меняет увиденное так же, как замысел.
  Граница видимого — в [PROCESS.md](../docs/conventions/PROCESS.md).
- **Одна ветка это одно изменение и один PR.** Прямых пушей в dev нет.
  Слияние squash одним коммитом без соавторства, тело сообщения PR это
  перечень изменений из диффа, а не пересказ намерений. Несвязанное
  разводится по веткам.
- **Модель агента выбирается по типу работы и записана в задании и в отчете.**
  Главная сессия (план, ответы владельца, решения) на самой сильной модели.
  Агентам: код с логикой Opus 5.5; безопасность и устройство модулей Fable 5.1,
  точечно; механика по готовому списку (удаление, переносы, прогоны, кадры,
  листы) Sonnet 5.5; чтение и сбор Haiku 5.5; ревью Opus 5.5, по безопасности
  Fable 5.1. Глубина мышления (effort) ниже на простых задачах. Дешевая модель
  дважды не прошла проверку: задача уходит на Opus 5.5. Смена модели молча
  запрещена: пин без строки в задании уводит работу на другую модель так, что
  владелец узнает об этом по результату.

## Скиллы и процесс

Процесс разработки собран из скиллов blueprint плюс наши дополнения и
описан в [PROCESS.md](../docs/conventions/PROCESS.md): выбор пути по типу
работы, где какой скилл останавливается, как `review` сочетается с агентом
[code-reviewer](agents/code-reviewer.md) (скилл — КАК смотреть, агент — ЧТО
искать), и как обновлять скиллы из апстрима. Агент вызывает скиллы сам, когда
задача совпадает с описанием; ручной вызов `/имя` — только чтобы заставить.

Оттуда же правила, которые чаще всего пропускают:

- Проектный документ проходит несколько кругов ревью свежими агентами, и в
  двух рамках: безопасность с корректностью отдельно, соразмерность с ценой
  отдельно.
- Проверенное утверждение несет доказательство на месте; непроверяемое либо
  помечено, либо удалено вместе с доводом, который на нем стоял.
- Тест обязан падать на сломанном коде, и это проверяется прогоном, а не
  предполагается. Вердикт гейта — код возврата команды, не хвост вывода.
- Видимое человеку закрывается живым стендом: тесты этот класс дефектов не
  ловят.
- Параллельные агенты правят каждый свою зону файлов, прогоны сборки и тестов
  разводятся по времени, коммитит оркестратор по именам файлов.

## Принципы документации

- **Минимум дублирования** — ссылки вместо копирования
- **Код > документация** — паттерны смотреть в коде
- **Только необходимое** — то, что нельзя узнать из кода
- **Конвенции, а не снимок состояния** — правило и идеал, к которому приводят код.
  Перечни файлов, имена классов, числа тестов, объемы сида и датированные сводки
  "сделано" устаревают на следующей же волне правок и в документацию не идут

Чек-лист ревью и перечень разобранных ложных срабатываний живут в
[code-reviewer](agents/code-reviewer.md), здесь они не повторяются.
