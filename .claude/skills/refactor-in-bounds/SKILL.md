# Рефакторинг в рамках

## Правила, на которых стоит порядок

Из [PROCESS.md](../../../docs/conventions/PROCESS.md): [вердикт гейта по коду возврата](../../../docs/conventions/PROCESS.md#вердикт-гейта-по-коду-возврата), [тест обязан падать на сломанном коде](../../../docs/conventions/PROCESS.md#тест-обязан-падать-на-сломанном-коде), прогоны разведены по времени ([зоны, прогоны, коммиты](../../../docs/conventions/PROCESS.md#зоны-прогоны-коммиты)). Откаты git агенту запрещены ([CLAUDE.md](../../CLAUDE.md)): HEAD остается началом задачи, а база и откат шага берутся из копии его файлов (шаг 3).

## Порядок

1. Записать рамки: файлы из задания и то, что остается прежним (вид, ответы сервера, поведение). Файл вне списка не правится, нужное в нем идет в отчет строкой "файл:строка, что". Если перенос ломает путь, по которому файл читают гейт-реестр или тест, а их нет в списке, шаг не делается.
2. Если задание поручает стенд, до первой правки снять его базу: `node scripts/visual/visual.mjs snap <метка> --rev HEAD` и `node scripts/visual/visual.mjs api-snap <метка> --rev HEAD`. Инструмент меряет уже запущенный стенд и ничего в нем не пересобирает. Условия, при которых снимок сравним, описаны в [scripts/visual/README.md](../../../scripts/visual/README.md), и читается он до первого снимка.
3. Перед каждым шагом затронутые им файлы копируются в scratchpad с раскладкой репозитория, из корня в Git Bash: `cp --parents <пути> <scratchpad>/<шаг>/`. Копия служит откатом шага и базой его сравнения по токенам, а сборку до шага сохраняет сам инструмент сравнения (шаг 5.3). Шаг, который не прошел, не чинится сверху новыми правками: он откатывается (`cp -r <scratchpad>/<шаг>/. .` из корня, созданные шагом файлы удаляются) и делится на шаги поменьше.
4. Шаги маленькие, в шаге один вид правки. Перенос и чистка идут отдельными шагами: при переносе код не переписывается, и сравнение показывает чистый перенос, а чистка следующим шагом видна своим диффом.
5. Каждый шаг доказан, от дешевого к дорогому:
   1. Компилятор и линт. Клиент, из `src/DM.Web.Client`: `npm run type-check` (четыре конфига, спеки и e2e в их числе) и `npx eslint --max-warnings 0 <файлы>`. Сервер, из корня: `dotnet build DM.sln`, предупреждение там ошибка.
   2. Тесты затронутого: из `src/DM.Web.Client` `npx vitest run <спеки и гейты-реестры>`, из корня `dotnet test <тестовый проект>` по затронутым модулям.
   3. Сравнение кода шага, из корня:
      - Перенос на клиенте сравнивается сборкой. До шага `node scripts/visual/compare-code.mjs --build --base-dir src/DM.Web.Client --save-base <scratchpad>/<шаг>-build --base-only`, после шага `node scripts/visual/compare-code.mjs --build --baseline <scratchpad>/<шаг>-build`.
      - Правка одних стилей так же, через `node scripts/visual/compare-css.mjs` с `--base-dir`, `--save-base <файл> --base-only` и `--baseline <файл>`.
      - Правка комментариев сравнивается по токенам, база только ревизия. Сначала `node scripts/visual/compare-code.mjs --head-dir <scratchpad>/<шаг> -- <пути>` показывает, что до шага файлы совпадали с HEAD по коду, затем `node scripts/visual/compare-code.mjs -- <пути>` сравнивает шаг. Поэтому правка комментариев идет раньше чистки тех же файлов.
   4. Стенд, если задание его поручает: `node scripts/visual/visual.mjs diff <метка>` по рабочему дереву для того, что рисуется. Ответы сервера `api-diff <метка>` берет у запущенного API, и серверную правку он доказывает только после пересборки API из дерева (`dm.ps1 e2e`, данные остаются), когда задание эту пересборку поручает. Без пересборки серверная правка не доказана, и так и пишется в отчете.
6. Неиспользуемое ищет компилятор, а не поиск по тексту. Поиск по тексту находит имя в комментарии, в строке и у чужого символа с тем же именем и не видит ссылку через реэкспорт. Список неиспользуемого до и после шага сокращается ровно на удаленное.
   - Клиент, из `src/DM.Web.Client`: `npx vue-tsc --noEmit -p tsconfig.app.json --composite false --noUnusedLocals --noUnusedParameters`, и так же по `tsconfig.vitest.json` для спеков. Неиспользуемые экспорты он не видит, их ищет разбор импортов и экспортов через TypeScript API, включая блоки `<script>` компонентов.
   - Сервер: IDE0005, IDE0051, IDE0052 и IDE0060 подняты в `.editorconfig` и включены в сборку через `EnforceCodeStyleInBuild`, поэтому `dotnet build <проект> --no-incremental` сам падает на неиспользуемом. Без `--no-incremental` проект, который не пересобирался, своих находок не печатает. Неприватное эти анализаторы не видят, его ищет поиск ссылок по семантической модели.
   - То, до чего добираются по строке (маршрут, регистрация через рефлексию, путь в тесте, `vi.mock`, ссылка шаблона `ref="..."`), компилятор не видит, а переменную, на которую шаблон ссылается через `ref="..."`, `vue-tsc` прямо называет неиспользуемой. Удаление такого помечается в отчете "не доказано до полного прогона волны": полные сюиты в шаге не гоняются.
7. Слияние модулей делается, только когда задание называет, что с чем сливается и какой интерфейс остается: это решение оркестратора.
   - Довод дает тест удаления: мысленно убрать модуль. Сложность исчезла, значит модуль транзитный и вливается в соседа. Расползлась по вызывающим, значит оправдан. Исполнитель, чье задание этот тест не проходит, пишет об этом в отчет, а не меняет решение.
   - У слитого модуля узкий интерфейс: наружу только то, что зовут вызывающие. Тесты идут через него и заменяют тесты мелких частей, а не наслаиваются.
   - Сравнение до и после такой шаг не доказывает. Он закрывается ревью свежего агента на модели по правилу [CLAUDE.md](../../CLAUDE.md), до ревью слияние не готово.

## Отчет

По каждому шагу: что сделано, файлы, команды доказательства с кодами возврата, для удаления неиспользуемого списки до и после. Отдельно: нужное в чужих файлах, удаленные файлы, удаления с пометкой "не доказано до полного прогона волны", серверные правки без пересборки API, шаги слияния, ждущие ревью, модель и глубина мышления, на которых шел агент.

## Границы

- Поведение и вид не меняются, даже когда правка очевидно лучше: такое уходит в отчет кандидатом.
- Тест, который перенос или слияние убирает, заменяется проверкой не слабее, и она проверяется на сломанном коде.
- Стенд, сброс, сид и пересборка API только по прямому поручению задания.
